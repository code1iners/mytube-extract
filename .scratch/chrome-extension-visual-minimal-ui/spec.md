# Chrome 확장 프로그램 시각 중심 최소 UI (A안 "무대")

## Problem Statement

Chrome 확장 프로그램의 Popup은 360px 폭 안에 제목·부제·테마 선택·정책 문구·썸네일 버튼 활성화 카드·URL 라벨과 설명·현재 탭 버튼·형식 라디오·파일명 라벨과 설명·품질 select와 설명·제출 버튼·최근 요청 목록을 모두 글자로 쌓아 둔다. 사용자는 다음을 겪는다.

- 지금 무엇을 추출하려는지 화면만 보고 알 수 없다. URL 문자열은 보여도 그 영상이 맞는지는 YouTube 탭으로 돌아가 확인해야 한다.
- YouTube 탭에서 Popup을 열어도 빈 URL 입력칸에서 시작한다. 매번 `현재 탭 사용` 버튼을 한 번 더 눌러야 한다.
- 진행 상태가 폼 아래의 짧은 문장 한 줄로만 보인다. 대기·처리·완료·실패를 구분하려면 문장을 읽어야 한다.
- 최근 요청이 글자 목록이라 어떤 영상이었는지 한눈에 알 수 없다.
- 썸네일 Overlay는 `MP3`·`MP4` 글자 버튼과 품질 패널을 거쳐 접수 토스트만 보여준다. 이후 그 영상이 어떻게 됐는지는 Overlay에서 알 수 없다.

## Solution

Popup과 썸네일 Overlay를 **글자를 최소화하고 썸네일·아이콘·형태로 상태를 말하는** A안("무대")으로 다시 구성한다. 승인된 시안은 `mockups/extension-a-states.html`이고, 비교안 B·C는 `mockups/extension-minimal-concepts.html`에 남긴다.

- Popup을 열면 현재 탭의 YouTube 영상이 **무대**(16:9 썸네일)에 바로 올라온다. YouTube 탭이 아니면 무대 자리에 붙여넣기 칸이 나타난다.
- 무대 아래에는 영상 제목 한 줄(=파일명, 연필로 편집), 형식 아이콘 두 칸, 품질 막대 세 개, 빨간 추출 버튼 하나만 둔다.
- 진행은 무대 위의 덮개와 링으로 보여준다: 서버 확인·대기·처리는 회전 링, 완료는 초록 체크, 실패는 어두운 덮개 위 crimson 아이콘과 오류 한 줄. 빨간 버튼은 실패 시 다시 시도 아이콘으로 바뀐다.
- 최근 요청은 상태 배지를 단 썸네일 줄로 보여주고, 누르면 썸네일 목록으로 펼쳐진다. 항목마다 행동 하나(다시 내려받기·다시 시도·다시 요청)가 있다.
- 테마, 썸네일 버튼 권한, 정책·보관 안내는 Popup 내부 설정 화면으로 옮긴다.
- 썸네일 Overlay는 형식 아이콘 두 개와 품질 막대 세 개로 바뀐다. 품질을 누르면 바로 접수되고, 그 썸네일 위에 대기·처리·완료·실패 상태가 남는다.

## User Stories

### 무대와 원본 지정

1. As a YouTube 영상을 보는 확장 사용자, I want Popup을 열자마자 현재 탭 영상의 썸네일과 제목을 보고 싶다, so that 무엇을 추출하는지 확인하는 단계를 건너뛸 수 있다.
2. As a YouTube 탭 사용자, I want 현재 탭 URL이 따로 버튼을 누르지 않아도 원본으로 지정되기를 원한다, so that 아이콘 클릭 한 번 뒤 바로 추출 버튼만 누르면 된다.
3. As a Shorts·youtu.be 링크를 보는 사용자, I want 지원하는 YouTube 주소 형식이면 모두 무대에 올라오기를 원한다, so that 주소 형식에 따라 동작이 달라지지 않는다.
4. As a YouTube가 아닌 탭에서 Popup을 연 사용자, I want 무대 자리에 붙여넣기 칸이 보이기를 원한다, so that 복사해 둔 주소를 바로 넣을 수 있다.
5. As a 키보드 사용자, I want 붙여넣기 칸에 포커스한 뒤 주소를 붙여넣거나 직접 타이핑할 수 있기를 원한다, so that 마우스 없이도 원본을 지정할 수 있다.
6. As a 잘못된 주소를 붙여넣은 사용자, I want 붙여넣기 칸이 오류 색으로 바뀌고 입력한 주소와 이유 한 줄이 보이기를 원한다, so that 무엇이 잘못됐는지 바로 알 수 있다.
7. As a 잘못된 주소를 넣은 사용자, I want 지우기 버튼으로 붙여넣기 칸을 다시 비우고 싶다, so that 다시 붙여넣을 수 있다.
8. As a 원본이 없거나 잘못된 상태의 사용자, I want 추출 버튼이 잠겨 보이기를 원한다, so that 제출할 수 없는 상태임을 글자 없이도 안다.
9. As a 썸네일 이미지를 불러오지 못한 사용자, I want 무대가 깨진 이미지 대신 중립 배경과 비디오 아이콘을 보여주기를 원한다, so that 화면이 망가져 보이지 않는다.
10. As a YouTube 탭에서 Popup을 연 사용자, I want 다른 영상 주소를 붙여넣어 원본을 바꿀 수 있기를 원한다, so that 현재 탭과 다른 영상도 추출할 수 있다.

### 파일명

11. As a 사용자, I want 무대 아래 제목이 저장될 파일명이라는 것을 연필 아이콘으로 알 수 있기를 원한다, so that 별도의 파일명 칸 없이도 이름을 바꿀 수 있다.
12. As a 사용자, I want 연필을 누르면 제목 줄이 입력칸과 확장자 표시로 바뀌기를 원한다, so that 어떤 형식으로 저장되는지 보면서 이름을 고칠 수 있다.
13. As a 사용자, I want Enter나 체크 버튼으로 파일명을 확정하고 싶다, so that 키보드와 마우스 모두로 편집을 끝낼 수 있다.
14. As a 사용자, I want 파일명을 비우고 확정하면 기본 이름(영상 제목 기반)으로 돌아가기를 원한다, so that 실수로 지워도 이름 없는 파일이 생기지 않는다.
15. As a 다른 영상으로 옮겨 간 사용자, I want 이전 영상에서 바꾼 파일명이 새 영상에 남지 않기를 원한다, so that 엉뚱한 이름으로 저장되지 않는다.

### 형식과 품질

16. As a 사용자, I want 오디오·비디오를 파형·필름 아이콘 두 칸으로 고르고 싶다, so that 글자를 읽지 않아도 형식을 고를 수 있다.
17. As a 사용자, I want 품질을 높이가 다른 막대 세 개로 고르고 싶다, so that 높을수록 품질이 높다는 것을 형태로 이해한다.
18. As a 사용자, I want 각 막대 아래에 실제 값(360·720·1080 또는 128·192·320)이 보이기를 원한다, so that 정확한 품질을 확인할 수 있다.
19. As a 사용자, I want 선택한 품질 이하의 막대가 모두 채워져 보이기를 원한다, so that 선택 수준을 한눈에 비교할 수 있다.
20. As a 재방문 사용자, I want 마지막으로 고른 형식과 품질이 기억되기를 원한다, so that 매번 다시 고르지 않아도 된다.
21. As a 스크린리더 사용자, I want 형식 버튼과 품질 막대가 각각 "오디오 MP3", "720p" 같은 이름과 선택 상태를 갖기를 원한다, so that 아이콘만 있어도 조작할 수 있다.

### 진행

22. As a 사용자, I want 추출 버튼을 누르면 무대 위에 회전 링이 나타나기를 원한다, so that 요청이 시작됐음을 바로 안다.
23. As a 사용자, I want 대기 중에는 링 안에 시계 아이콘이 보이기를 원한다, so that 아직 차례를 기다리는 중임을 구분할 수 있다.
24. As a 사용자, I want 처리 중에는 숫자 없는 회전 링을 보고 싶다, so that 실제가 아닌 진행률에 속지 않는다.
25. As a 사용자, I want 진행 중에는 형식·품질이 잠기고 추출 버튼이 회색 회전 아이콘이 되기를 원한다, so that 같은 요청을 중복으로 보내지 않는다.
26. As a 사용자, I want 완료되면 무대가 잠깐 초록 체크로 덮였다가 준비 상태로 돌아오기를 원한다, so that 다운로드가 시작됐음을 확인하고 바로 다음 요청을 할 수 있다.
27. As a Popup을 닫았다 다시 연 사용자, I want 같은 영상의 요청이 진행 중이면 무대에 그 진행 상태가 다시 보이기를 원한다, so that 요청을 잃었다고 착각하지 않는다.
28. As a 스크린리더 사용자, I want 진행 단계가 바뀔 때마다 "서버 확인 중", "대기 중", "처리 중", "다운로드를 시작했어요"가 읽히기를 원한다, so that 시각 링 없이도 상태를 안다.

### 문제

29. As a 추출이 실패한 사용자, I want 무대가 어두운 덮개와 crimson 경고 아이콘으로 바뀌고 서버가 준 이유가 한 줄로 보이기를 원한다, so that 왜 실패했는지 알 수 있다.

31. As a 실패를 겪은 사용자, I want 같은 빨간 버튼이 다시 시도 아이콘으로 바뀌기를 원한다, so that 같은 자리에서 같은 조건으로 바로 재시도할 수 있다.
32. As a 사용자, I want 모든 오류 문장이 한국어이기를 원한다, so that 영어 문장이 섞여 나오지 않는다.

### 최근 요청

33. As a 사용자, I want 추출 버튼 아래에 최근 요청 썸네일 최대 세 개와 더보기 버튼이 보이기를 원한다, so that 최근 무엇을 요청했는지 영상으로 기억할 수 있다.

36. As a 사용자, I want 목록 항목마다 썸네일, 영상 제목, 형식 아이콘과 품질, 요청 시각, 상태 아이콘과 상태명이 보이기를 원한다, so that 요청을 구분할 수 있다.
37. As a 완료 요청을 다시 받고 싶은 사용자, I want 완료 항목의 다시 내려받기 버튼을 원한다, so that 보관 기간 안에는 재처리 없이 파일을 다시 받을 수 있다.
38. As a 실패 요청을 다시 시도하려는 사용자, I want 실패 항목의 다시 시도 버튼을 원한다, so that 원래 조건으로 다시 접수할 수 있다.
39. As a 만료된 요청을 다시 받고 싶은 사용자, I want 만료 항목의 다시 요청 버튼을 원한다, so that 원래 조건으로 새 요청을 만들 수 있다.
40. As a 처음 사용하는 사용자, I want 최근 요청이 없으면 빈 상자 아이콘만 보이기를 원한다, so that 비어 있음을 안다.

54. As a Overlay 사용자, I want 실패하면 그 썸네일 위 배지가 다시 시도 버튼이 되기를 원한다, so that 같은 조건으로 그 자리에서 재시도할 수 있다.
55. As a Overlay 사용자, I want 접수·실패 토스트가 미니 썸네일, 상태 아이콘, 형식과 품질, 닫기(실패면 다시 시도 포함)로 보이기를 원한다, so that 페이지를 가리는 문장 없이 결과를 확인한다.
56. As a 무한 스크롤이나 페이지 이동을 하는 사용자, I want 같은 영상 카드가 다시 나타나면 그 영상의 현재 상태가 다시 표시되기를 원한다, so that 카드가 다시 그려져도 상태를 잃지 않는다.
57. As a 스크린리더 사용자, I want Overlay 버튼과 상태 배지·토스트가 접근 가능한 이름과 live region 문장을 갖기를 원한다, so that 아이콘만 있어도 결과를 들을 수 있다.

### 공통

58. As a 다크 모드 사용자, I want Popup과 Overlay 상태 화면이 다크 토큰에서도 같은 대비를 유지하기를 원한다, so that 어느 테마에서든 상태를 구분할 수 있다.
59. As a 키보드 사용자, I want 모든 조작을 읽기 순서대로 Tab으로 이동하고 파란 포커스 링으로 확인하고 싶다, so that 마우스 없이 전체 흐름을 쓸 수 있다.
60. As a 움직임을 줄인 사용자, I want 회전·덮개 전환 애니메이션이 줄어든 동작 설정에서 멈추기를 원한다, so that 어지럽지 않게 상태를 볼 수 있다.

## Implementation Decisions

### 범위와 기존 결정 변경

- **현재 탭 자동 읽기로 바꾼다.** 기존 PRD의 "URL 직접 입력이 기본, 현재 탭 가져오기는 버튼을 누를 때만, `activeTab`도 그때만 사용" 결정을 대체한다. Popup은 열릴 때 활성 탭 URL을 한 번 읽고, 지원 YouTube 주소이면 원본으로 지정한다. 아이콘 클릭으로 이미 `activeTab`이 부여되므로 manifest 권한은 늘리지 않는다. `현재 탭 사용` 버튼은 제거한다.
- **Overlay 진행 표시를 넣는다.** 이전 job 전환 스펙의 "Overlay는 접수 토스트만, 진행은 알림과 Popup이 담당" 결정을 대체한다. 데스크톱 알림과 자동 다운로드는 그대로 유지한다.
- **진행 퍼센트는 표시하지 않는다.** API의 `progress`는 상태 기반 값(대기 0, 처리 50, 완료 100)이라 실제 진행률이 아니다. `DESIGN.md`의 "수치가 있을 때만 진행률" 규칙에 따라 처리 중에도 숫자 없는 회전 링을 쓴다. 시안의 퍼센트 표기는 반영하지 않는다.
- **영상 길이는 표시하지 않는다.** Popup이 근거 있게 얻을 출처가 없어서 시안의 길이 칩은 뺀다.
- API와 서버 계약은 바꾸지 않는다.

### Popup 화면 모델

- Popup 안에 화면 세 개를 둔다: `main`(무대), `recent`(최근 요청), `settings`(설정). 라우트가 아니라 Popup 내부 상태이고, Popup을 다시 열면 항상 `main`에서 시작한다.
- 화면 상태는 `PopupDownloadModel` snapshot에서 **도출**한다. React 컴포넌트는 도출된 값만 그리는 얇은 층으로 둔다. 시안 렌더러가 이 상태 모양을 쓰고 있고, 아래는 그 핵심을 정리한 것이다(시안 프로토타입에서 가져옴).

```ts
type StageSource =
  | { kind: 'tab' | 'pasted'; videoId: string; title: string | null; thumbnailUrl: string }
  | { kind: 'empty' }                        // missing-source-url
  | { kind: 'invalid'; input: string };      // invalid-source-url

type StagePhase =
  | 'idle'        // ready
  | 'checking'    // checking-server 또는 submitting
  | 'queued'      // job-queued
  | 'processing'  // job-processing (숫자 없음)
  | 'done'        // download-started, 잠시 뒤 idle로 복귀
  | 'failed'      // job 실패 또는 서버가 거부한 접수
  | 'unreachable';// 서버 연결 실패

type PopupView = 'main' | 'recent' | 'settings';
```

- `StagePhase`는 현재 무대 영상에 해당하는 최신 job의 상태를 우선한다. 다른 영상의 job 진행은 무대에 영향을 주지 않고 최근 요청 줄에만 반영한다. 기존의 "여러 job을 독립적으로 추적하고 처리 중에도 새 요청 허용" 동작은 유지한다. 단 무대 영상의 job이 진행 중이면 그 영상에 대한 제출만 잠근다.
- `done`은 약 1.8초 뒤 `idle`로 돌아간다. 이 전환은 화면 표시 상태이며 job 상태를 바꾸지 않는다.
- 실패 종류를 구분하려고 Popup 상태에 실패 원인 구분을 추가한다: job 실패·접수 거부(`failed`, 서버 메시지 표시)와 네트워크·서버 연결 실패(`unreachable`). 오류 문장은 모두 한국어로 바꾼다. 영어 문장(`Download failed. Please try again.`, `Could not save extension settings.` 등)도 대상이다.

### 원본과 영상 정보

- 영상 ID는 기존 URL 정규화로 얻는다. 썸네일은 영상 ID로 만드는 YouTube 이미지 주소를 쓴다. 이미지 로드는 host permission이 필요 없다. 로드에 실패하면 중립 배경과 비디오 아이콘으로 대체한다.
- 제목은 활성 탭 제목에서 YouTube 접미사를 뗀 값을 쓴다. 붙여넣은 주소처럼 제목을 알 수 없으면 영상 ID를 표시한다. 접수 후에는 API 응답의 요청 영상 제목이 있으면 그것을 쓴다.
- 붙여넣기 칸은 실제 텍스트 입력을 가진 접근 가능한 control이다. 붙여넣기와 타이핑 모두 기존 `sourceUrl` 갱신 경로를 그대로 쓴다. 원본 URL은 지금처럼 저장하지 않는다(session-only).

### 파일명

- 무대 아래 제목 줄이 파일명이다. 편집하지 않으면 지금처럼 기본 이름(오버레이와 같은 제목 기반 정리, 실패 시 영상 ID)을 쓴다.
- **파일명을 더 이상 저장소에 저장하지 않는다.** 영상별 값이 되므로 원본 영상이 바뀌면 비운다. 기존에는 파일명이 다른 옵션과 함께 저장됐다. 형식·품질은 계속 저장한다.
- 편집 입력은 확장자(`.mp3`/`.mp4`)를 옆에 보여준다. 확정은 Enter 또는 체크 버튼, 빈 값 확정은 기본 이름으로의 복귀다. 기존 파일명 sanitize는 유지한다.

### 형식·품질·버튼

- 형식은 아이콘 토글 두 개(파형 = 오디오 MP3, 필름 = 비디오 MP4), 품질은 기존 고정 선택지 세 개를 radiogroup 막대로 보여준다. 선택한 값 이하의 막대를 채운다.
- 추출 버튼 상태:

| 상태 | 버튼 |
| --- | --- |
| 원본 없음·잘못됨 | 잠김(회색, 다운로드 아이콘) |
| `idle`·`done` | 빨강, 다운로드 아이콘, "추출 시작" |
| `checking`·`queued`·`processing` | 잠김, 파란 회전 아이콘 |
| `failed`·`unreachable` | 빨강, 다시 시도 아이콘, "다시 시도" (같은 조건 재제출) |

### 최근 요청

- 확장의 job 표현에 API 응답의 `sourceUrl`과 요청 영상 제목을 보존한다. 영상 ID는 `sourceUrl`에서 도출한다. 클라이언트 매핑만 바뀌고 API는 그대로다. 이 필드가 없는 기존 저장 job은 썸네일 대신 중립 배경과 형식 아이콘을 보여준다.
- 최대 5건 보관 정책과 진행 중 job 보호는 그대로 둔다. 무대 아래 줄은 최신 세 개와 더보기 버튼만 보여준다.
- 목록 항목의 행동:
  - 완료: 다시 내려받기. 보관 기간 안의 `downloadUrl`로 로컬 다운로드를 다시 시작한다.
  - 실패: 다시 시도. 만료: 다시 요청. 둘 다 job의 원본·형식·품질로 새 job을 제출하고, 파일명은 기본 이름을 쓴다.
  - 대기·처리: 행동 없이 상태 아이콘만 둔다.
- Popup에서의 재제출은 알림 재시도와 같은 background 제출 경로를 쓴다.

### 설정과 권한

- 설정 화면 구성: 테마 선호 세 칸(기존 저장 방식 유지), 썸네일 버튼 행, 정책 안내, 보관 기간 안내(job의 `retentionDays`, 기본 7일).
- 썸네일 버튼 행의 상태: 꺼짐(스위치) → 켜기 누름(권한 요청, 회전 아이콘) → 켜짐(스위치 on) / 거부·오류(crimson 행, 이유 한 줄, 다시 요청 버튼).
- **권한 해제를 추가한다.** 스위치를 끄면 YouTube optional host permission을 제거하고, 이후 자동 주입이 멈춘다. 이를 위해 Overlay 권한 adapter에 해제 동작을 추가한다. 이미 열린 탭의 버튼은 다음 이동이나 새로고침 때 사라져도 된다.
- 헤더의 격자 아이콘은 권한 상태 점을 보여주고, 누르면 설정 화면을 연다.

### 썸네일 Overlay

- 호버 UI는 형식 원형 아이콘 버튼 두 개와 품질 막대 세 개로 바꾼다. 기존 `MP3`·`MP4` 글자 버튼과 품질 패널을 대체한다. Overlay의 형식 선택은 같은 페이지 안에서만 기억한다. 품질 막대를 누르면 기존 Overlay 다운로드 메시지로 바로 제출한다.
- **진행 표시는 새 background→content 메시지를 만들지 않는다.** Overlay 스크립트가 저장된 최근 요청 목록의 변경을 구독한다. 구독 방식은 Popup과 같은 storage 변경 이벤트다. 각 카드의 영상 ID와 job의 영상 ID를 매칭해 상태를 그린다. 그래서 최근 5건 보관 목록에 있는 job만 Overlay에 표시된다.
- 카드 위 상태: 대기는 시계와 회전 링, 처리는 회전 링, 완료는 초록 체크 배지(몇 초 뒤 사라짐), 실패는 crimson 다시 시도 버튼 배지. 실패 배지를 누르면 같은 형식·품질로 재제출한다. 상태 배지는 호버와 관계없이 보인다. 카드가 다시 그려져도 같은 매칭으로 다시 표시한다.
- 토스트: 미니 썸네일, 상태 아이콘, 형식 아이콘과 품질, 닫기 버튼. 실패 토스트에는 다시 시도 버튼을 더한다. 문장은 화면에 보이지 않고 live region으로만 전달한다.
- 기존 Shadow Root 격리, Shorts 제외, 동적 카드 대응, 중복 주입 방지는 유지한다.

### 시각 계약

- 토큰은 `DESIGN.md` semantic token을 그대로 쓴다. Nintendo red는 추출·다시 시도 버튼, 선택 표시, 로고에만 쓴다. 상태색은 대기 회색, 처리 파랑, 완료 초록, 실패 crimson으로 배지·아이콘에만 쓴다. 무대 위 링은 흰색이고, 실패 덮개는 어두운 scrim에 crimson 아이콘이다.
- 화면에 남는 글자는 영상 제목, 품질 숫자, 오류 한 줄, 설정 행 이름·안내, 최근 요청 목록의 메타 정보로 제한한다. 나머지 의미는 아이콘과 접근 가능한 이름이 맡는다.
- 접근성: 모든 아이콘 버튼에 접근 가능한 이름을 단다. 상태는 색과 아이콘을 함께 쓰고 live region 문장을 둔다. 조작 영역은 44×44px 이상이다(시안의 36px 연필 버튼도 44px로 키운다). 포커스는 파란 outline, 줄어든 동작 설정에서는 회전·전환 애니메이션을 끈다. 200% 글자 확대에서 조작이 가려지지 않아야 한다.
- 문서 갱신: `DESIGN.md`에 Chrome popup·Overlay 최소 UI 계약 절을 추가하고, 확장 PRD·FSD의 현재 탭·Overlay 진행 표시·파일명 저장 서술을 이 스펙에 맞춰 고친다. 필요하면 글로서리에 "무대" 용어를 추가한다.

## Testing Decisions

- 좋은 테스트는 외부 동작만 검증한다. 가짜 adapter를 주입한 model의 입력(초기화, 옵션 변경, 제출, background job 변경)에 대해 snapshot과 도출된 화면 상태가 어떻게 바뀌는지를 본다. 내부 함수 호출 순서나 CSS 클래스는 검증하지 않는다.
- **주 seam은 `PopupDownloadModel` 통합 테스트다.** 기존 integration 테스트를 확장한다. 다룰 것:
  - 지원 YouTube 탭에서 열면 원본이 자동으로 지정되고 무대 원본이 `tab`이다.
  - YouTube가 아닌 탭에서는 `empty`, 잘못된 입력은 `invalid`이며 제출이 잠긴다.
  - 제출에서 `checking` → `queued` → `processing` → `done` → `idle` 순서로 전이한다.
  - job 실패는 `failed`와 서버 메시지, 연결 실패는 `unreachable`로 구분된다.
  - 다른 영상의 job 진행은 무대 phase를 바꾸지 않는다.
  - 파일명은 저장되지 않고, 원본이 바뀌면 비워진다. 형식·품질은 계속 저장된다.
  - 최근 요청 항목의 재제출과 다시 내려받기가 올바른 입력으로 bridge·downloads를 호출한다.
  - 권한 켜기·끄기·거부 상태가 전이한다.
  - 기존 "현재 탭 자동 감지 대신 입력 필요" 테스트는 새 결정에 맞게 고친다.
- **브라우저 seam은 기존 Playwright 스모크다.** popup 스모크는 built popup에서 무대·붙여넣기 칸·잘못된 주소·서버 실패·다운로드 흐름과 설정의 권한 흐름을 실제 렌더링으로 확인한다. overlay 스모크는 새 호버 UI(아이콘·막대), 품질 클릭 제출, 저장된 job 변경에 따른 카드 상태 배지, 실패 배지 재시도, 토스트, Shorts 제외, 동적 카드를 확인한다.
- **계약 seam은 기존 단위 테스트를 확장한다.** Overlay 다운로드 메시지 계약 테스트는 그대로 유지한다. job 매핑에 `sourceUrl`·제목 보존이 더해지므로 client·storage adapter 단위 테스트를 함께 확장한다. Overlay 권한 adapter 테스트에 해제 동작을 추가한다.
- 새 seam(React 컴포넌트 렌더 테스트 등)은 만들지 않는다.
- 선례: 기존 popup model integration 테스트, `popup-smoke`·`youtube-overlay-smoke`·`youtube-overlay-visibility-smoke` 브라우저 테스트, `youtube-overlay-contract`·`youtube-overlay-adapter`·`download-job-storage-adapter`·`mytube-extract-client` 단위 테스트.

## Out of Scope
