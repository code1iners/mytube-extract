# 01: 잘못된 파일을 놓아도 기존 선택 보존

Status: ready-for-agent

**What to build:** Web 앱의 자막 추출 화면에서 잘못된 파일을 놓아도 기존 영상과 처리 방식을 유지한다. 방금 놓은 파일이 거부되었다는 오류를 안내하고, 정상 파일을 다시 놓으면 새 영상으로 선택을 갱신한다.

**Blocked by:** 없음 — 즉시 시작 가능.

## 완료 조건

- [ ] 놓은 파일을 기존 자막 파일 검증으로 확인한 뒤 정상 파일만 현재 선택으로 반영한다. 확장자와 파일 형식의 기존 허용 목록을 완화하지 않는다.
- [ ] 정상 영상이 선택된 상태에서 잘못된 파일을 놓으면 기존 영상의 이름·메타 정보·처리 방식과 제출 대상이 유지된다. 오류는 방금 놓은 파일에 대한 것으로 명확히 안내한다.
- [ ] 거부한 파일의 오류 안내와 현재 선택 영상의 유효성을 구분한다. 유지된 정상 영상의 제출 가능 여부는 해당 영상과 기존 요청 상태로 결정한다.
- [ ] 기존 선택이 없을 때 잘못된 파일을 놓으면 빈 상태와 오류 안내를 표시하고 제출 불가 상태를 유지한다.
- [ ] 정상 파일을 다시 놓으면 선택을 교체하고 이전 파일 입력 오류를 해제한다. 세 가지 지원 형식 `mp4`, `mov`, `webm`이 기존 선택 경로로 이어진다.
- [ ] 지원 MIME (영문 원문: Multipurpose Internet Mail Extensions: 파일 형식을 나타내는 표준 식별 정보)에 비지원 확장자가 붙은 파일과 실제 MIME이 빈 파일도 기존 기준대로 거부한다.
- [ ] 복수 파일은 현재처럼 첫 파일을 대상으로 판단한다. 파일이 없는 링크·텍스트 드롭은 현재 선택을 지우지 않는다. 파일 놓기가 브라우저의 파일 열기 동작으로 이어지지 않는다.
- [ ] 파일 선택 대화상자의 기존 선택·취소 동작, 처리 방식, 용량 초과 오류 경로와 추출 요청 생명주기를 유지한다.

## 검증

- [ ] 기존 자막 화면 브라우저 테스트에서 정상 선택 → 잘못된 파일 놓기 → 기존 선택 유지 → 정상 파일 재선택 경로를 검증한다. 내부 상태명이나 스타일 클래스만 검사하지 않는다.
- [ ] 기존 선택이 없는 경우, 형식 불일치, 빈 MIME, 복수 파일의 첫 파일 처리, 파일이 없는 드롭을 검증한다.
- [ ] 기존의 “정상 선택 후 잘못된 파일을 놓으면 제출 불가” 기대값을 선택 보존 계약으로 수정한다. 이름·메타 정보뿐 아니라 보존된 영상이 실제 제출 대상임을 기존 브라우저 테스트의 요청 관찰 경계에서 확인한다.
- [ ] 기존 파일 검증 단위 테스트와 화면 마크업 테스트를 필요한 범위에서 보완하고, 마지막 변경 후 Web 정적 검사·단위 테스트·관련 브라우저 테스트 결과를 기록한다.

## 범위와 인계

- 드래그 위치 강조와 사전 불가 표시는 후속 티켓 범위다. 이 티켓은 기존 드롭 경로만으로 독립 검증할 수 있다.
- 서버·저장소·접수증 계약이나 지원 형식을 변경하지 않는다. 별도 선행 리팩터링 티켓을 만들지 않는다.
- 실제 운영체제 드래그의 통합 확인은 03번에서 수행한다. 이 티켓의 합성 드롭 검증을 실제 파일 관리자 드래그의 증거로 기록하지 않는다.
