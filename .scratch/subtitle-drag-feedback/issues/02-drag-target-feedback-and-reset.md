# 02: 드래그 위치 강조와 안정적인 복원

Status: ready-for-agent

**What to build:** 자막 추출의 `영상 선택 또는 드래그` 박스 전체가 파일 진입에 반응한다. 배경·테두리·안내 문구로 놓을 위치를 알려 주며, 내부 이동 중에는 깜빡이지 않고 이탈·취소·놓기 후 원래 표시로 돌아간다.

**Blocked by:** 없음 — 즉시 시작 가능. 01번의 선택 보존 없이도 현재 드롭 경로에서 독립 검증할 수 있다.

## 완료 조건

- [ ] 파일이 박스에 진입하면 배경과 테두리를 강조하고 주요 문구를 `여기에 놓아 영상을 선택하세요`로 바꾼다. `mp4, mov, webm` 안내는 유지한다.
- [ ] 강조는 놓을 위치 안내로 표현하며, 최종 파일 유효성이나 추출 성공을 보장하는 표현을 사용하지 않는다. 이 티켓에서는 파일 형식의 사전 거부를 구현하지 않는다.
- [ ] 아이콘과 문구 등 박스 내부 요소 사이를 이동해도 강조가 유지된다. 실제 영역 이탈·드래그 취소·파일 놓기·화면 전환 후에는 강조가 남지 않는다.
- [ ] 기존 파일 오류가 있으면 드래그 중 위치 강조를 우선하되 기존 오류 문구는 보존한다. 놓지 않고 벗어나면 기존 오류 테두리와 일반 문구로 돌아간다.
- [ ] 진입·이탈·취소만으로 선택 영상, 처리 방식, 기존 오류 또는 업로드 관련 상태를 변경하지 않는다. 놓기 시에는 드래그 표시를 해제하고 해당 시점의 기존 파일 선택 경로로 연결한다.
- [ ] 파일 목록을 놓기 전에 읽을 수 있다고 가정하지 않는다. 링크·텍스트처럼 파일이 아닌 드래그를 파일 진입으로 오인하지 않는다.
- [ ] 기존 의미별 디자인 토큰을 사용하고, 박스 크기와 주변 배치를 유지한다. 확대·이동·바운스·강한 그림자를 추가하지 않는다.
- [ ] 라이트·다크 테마에서 강조와 기존 오류를 구분할 수 있다. 접근 가능한 버튼 이름, 오류 연결, 키보드 포커스 표시와 클릭·Enter·Space 파일 선택을 유지한다.
- [ ] 반복되는 드래그 이벤트마다 동일한 상태 알림을 재생하지 않는다.

## 검증

- [ ] 기존 자막 화면 브라우저 테스트를 확장해 진입 시 실제 표시 변화, 내부 이동 시 유지, 이탈·취소·놓기 후 복원을 확인한다. 단순 클래스 존재나 내부 카운터를 완료 근거로 삼지 않는다.
- [ ] 드래그 중 파일 목록에 접근할 수 없는 조건, 기존 오류가 있는 조건, 파일이 아닌 드래그를 포함한다.
- [ ] 라이트·다크 테마 및 좁은 화면에서 문구 넘침·박스 크기 변화·주변 배치 이동을 확인한다. 기존 클릭·키보드 파일 선택과 실제 포커스 표시를 회귀 확인한다.
- [ ] 실제 운영체제 파일 관리자에서 지원 영상을 브라우저로 드래그해 진입·내부 이동·이탈·취소·놓기를 확인한다. 운영체제·브라우저와 관찰 결과를 기록하며, 수행하지 못한 경계는 미검증으로 남긴다.
- [ ] 마지막 변경 후 Web 정적 검사·단위 테스트·관련 브라우저 테스트 결과를 기록한다. 합성 이벤트나 정적 마크업 결과를 실제 파일 드래그 성공으로 표현하지 않는다.

## 범위와 인계

- 01번과 논리적 선행 관계는 없지만 같은 화면의 입력 처리를 수정할 수 있다. 같은 작업 디렉터리에서 동시 편집한다면 변경 충돌을 조정한다.
- 비지원 형식의 사전 불가 표시는 03번에서 추가한다. 01번의 선택 보존을 이 티켓의 완료 조건으로 요구하지 않는다.
- 추출 요청 생명주기, 파일 검증 기준, 서버 계약과 파일 선택 대화상자 정책은 변경하지 않는다.
