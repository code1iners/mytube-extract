# 자막 추출 파일 드래그 피드백과 기존 선택 보존

확정일: 2026-09-08

## Problem Statement

Web 앱의 자막 추출 화면에는 `영상 선택 또는 드래그` 박스가 있지만, 현재는 일반 마우스 hover 효과만 있고 파일을 드래그해 올려놓았다는 별도 표시가 없다. 사용자는 놓을 위치에 진입했는지, 지원하지 않는 파일인지 구분하기 어렵다.

현재 파일을 놓으면 먼저 선택을 교체한 뒤 형식을 검증한다. 이미 정상 영상을 선택했더라도 잘못된 파일을 놓으면 기존 선택을 잃는다. 위치 안내와 파일 거부 안내를 구분하고, 잘못된 드롭으로 이전 선택이 사라지지 않게 해야 한다.

## Solution

기존 파일 선택 박스 전체를 반응 영역으로 사용한다. 파일을 드래그해 진입하면 배경과 테두리를 강조하고 문구를 `여기에 놓아 영상을 선택하세요`로 바꾼다. 강조는 놓을 위치 안내이며, 파일의 최종 사용 가능 여부나 추출 성공을 보장하지 않는다.

드래그 중 명확히 지원하지 않는 형식이 확인되면 오류색 테두리, 금지 아이콘, `지원하지 않는 파일 형식입니다` 문구를 표시한다. 형식을 확인할 수 없으면 위치 안내를 유지하고 놓은 뒤 기존 형식 검증으로 판단한다.

영역 이탈, 드래그 취소, 파일 놓기 후에는 드래그 표시를 해제한다. 잘못된 파일을 놓으면 새 파일의 오류만 안내하며 기존 선택 영상과 처리 방식은 유지한다. 기존 선택이 없으면 빈 상태를 유지한다.

## User Stories

1. 자막 추출 사용자로서, 파일을 박스에 드래그하면 박스 전체가 반응하기를 원한다. 그래야 파일을 놓을 위치에 진입했음을 알 수 있다.
2. 자막 추출 사용자로서, 드래그 중 배경과 테두리가 함께 달라지기를 원한다. 그래야 일반 상태와 드래그 상태를 구분할 수 있다.
3. 자막 추출 사용자로서, 드래그 중 `여기에 놓아 영상을 선택하세요`라는 안내를 원한다. 그래야 다음 행동을 알 수 있다.
4. 자막 추출 사용자로서, 명확한 비지원 형식에는 오류색과 금지 아이콘, 설명 문구가 함께 나타나기를 원한다. 그래야 색만으로 의미를 추측하지 않아도 된다.
5. 자막 추출 사용자로서, 형식 정보가 없는 파일은 미리 거부되지 않기를 원한다. 그래야 실제 파일을 놓은 뒤 검증받을 수 있다.
6. 자막 추출 사용자로서, 위치 강조가 추출 가능 확정으로 표현되지 않기를 원한다. 그래야 최종 검증 전 잘못된 기대를 갖지 않는다.
7. 자막 추출 사용자로서, 박스 내부의 아이콘과 문구 사이를 이동해도 강조가 유지되기를 원한다. 그래야 표시가 깜빡이거나 놓을 영역을 벗어났다고 오해하지 않는다.
8. 자막 추출 사용자로서, 파일을 놓지 않고 박스를 벗어나면 이전 표시로 돌아가기를 원한다. 그래야 현재 위치를 정확히 알 수 있다.
9. 자막 추출 사용자로서, 드래그를 취소하거나 파일을 놓은 뒤 강조가 남지 않기를 원한다. 그래야 현재 상태와 화면 표시가 일치한다.
10. 자막 추출 사용자로서, 기존 오류가 있어도 새 파일을 드래그하는 동안 위치 안내를 볼 수 있기를 원한다. 그래야 다시 선택하는 방법을 알 수 있다.
11. 자막 추출 사용자로서, 새 파일을 놓기 전까지 기존 오류 설명이 유지되기를 원한다. 그래야 아직 해결되지 않은 문제를 확인할 수 있다.
12. 자막 추출 사용자로서, 잘못된 파일을 놓아도 기존 정상 영상이 유지되기를 원한다. 그래야 같은 영상을 다시 선택하지 않아도 된다.
13. 자막 추출 사용자로서, 기존 영상이 없는 상태에서 잘못된 파일을 놓으면 빈 상태와 오류 안내가 표시되기를 원한다. 그래야 사용할 수 없는 파일이 선택된 것처럼 보이지 않는다.
14. 자막 추출 사용자로서, 정상 파일을 놓으면 해당 영상으로 선택이 갱신되기를 원한다. 그래야 기존 방식대로 자막 추출을 이어갈 수 있다.
15. 자막 추출 사용자로서, 오류 안내가 방금 놓은 파일에 대한 것임을 알 수 있기를 원한다. 그래야 유지된 정상 영상이 잘못되었다고 오해하지 않는다.
16. 자막 추출 사용자로서, 파일을 거부하더라도 선택한 처리 방식이 유지되기를 원한다. 그래야 설정을 반복하지 않아도 된다.
17. 자막 추출 사용자로서, 드래그 상태가 바뀌어도 박스 크기와 주변 배치가 유지되기를 원한다. 그래야 목표 위치가 움직이지 않는다.
18. 라이트·다크 테마 사용자로서, 두 테마 모두에서 위치 안내와 불가 표시를 구분할 수 있기를 원한다. 그래야 테마에 관계없이 같은 작업을 수행할 수 있다.
19. 키보드·터치 사용자로서, 기존 파일 선택 버튼과 키보드 포커스가 유지되기를 원한다. 그래야 드래그를 사용하지 않아도 영상을 선택할 수 있다.

## Implementation Decisions

### 변경 경계

- 자막 추출 화면의 표시와 해당 화면의 파일 입력 상태·드래그 이벤트 처리를 변경한다. 기존 자막 파일 검증 모듈을 재사용한다.
- 드래그 피드백과 마지막으로 거부한 파일의 안내를 현재 선택 영상의 유효성과 구분한다. 잘못된 파일을 현재 선택으로 넣어 오류를 표현하지 않는다.
- 파일 놓기에 대한 선택 보존이 이번 동작 변경의 범위다. 파일 선택 대화상자의 기존 선택·취소 정책을 함께 재설계하지 않는다.
- 추출 요청 생명주기, 접수증, 처리 방식, 업로드 프로토콜, 서버 계약은 유지한다. 데이터 저장 구조나 외부 의존성을 추가하지 않는다.

### 표시 상태와 우선순위

| 상태 | 박스 표시 | 안내 |
| --- | --- | --- |
| 드래그 없음 | 기존 일반·hover·오류 표시 | `영상 선택 또는 드래그` 및 기존 안내 |
| 파일 진입, 지원 형식 또는 정보 불명확 | 배경·테두리 강조 | `여기에 놓아 영상을 선택하세요` |
| 파일 진입, 명확한 비지원 형식 | 오류색 테두리·금지 아이콘 | `지원하지 않는 파일 형식입니다` |
| 이탈·취소 | 드래그 이전 일반 또는 오류 표시로 복원 | 기존 안내 유지 |
| 놓기 | 드래그 표시 해제 후 실제 검증 결과 표시 | 정상 선택 또는 새 파일 거부 안내 |

- `mp4, mov, webm` 형식 안내를 유지한다.
- 기존 오류가 있어도 드래그 중에는 위 드래그 상태 표시를 우선한다. 기존 오류 문구는 남기며, 파일을 놓지 않고 나가면 기존 오류 테두리로 복원한다.
- 아이콘·문구 등 박스 내부 요소 사이의 이동을 영역 이탈로 처리하지 않는다. 실제 이탈·취소·화면 전환 후 드래그 강조가 남지 않게 한다.
- 박스의 높이·너비와 문구 영역을 안정적으로 유지한다. 확대·이동·바운스·강한 그림자 효과를 추가하지 않는다.
- 기존 디자인의 의미별 색상 토큰을 사용한다. 불가 표시는 브랜드 액션 빨강이 아닌 오류색을 사용한다. 라이트·다크 테마와 기존 키보드 포커스 표시를 유지한다.
- 오류와 상태를 색만으로 전달하지 않는다. 기존 접근 가능한 버튼 이름, 오류 연결과 알림을 유지하며 반복되는 드래그 이벤트마다 같은 알림을 재생하지 않는다.

### 드래그 중 판정과 최종 검증

- MIME (영문 원문: Multipurpose Internet Mail Extensions: 파일 형식을 나타내는 표준 식별 정보) 등 브라우저가 드래그 중 제공하는 형식 정보만으로 사전 안내한다. 이 단계에서 파일 이름·확장자·용량·내용을 읽을 수 있다고 가정하지 않는다.
- `image/png`, `text/plain` 등 명확한 비지원 형식은 불가 표시한다. 빈 형식, 일반 바이너리 형식처럼 특정 파일 형식을 판별할 수 없는 정보는 불명확으로 취급한다.
- 지원 형식 정보가 있어도 위치 안내만 한다. 놓은 뒤에는 확장자 `mp4`, `mov`, `webm`과 MIME `video/mp4`, `video/quicktime`, `video/webm`을 각각 허용 목록으로 확인하는 기존 검증을 적용한다. 지원 MIME에 비지원 확장자가 붙은 파일도 거부한다.
- 실제 파일의 MIME이 빈 문자열이면 기존 최종 검증은 거부한다. 드래그 중 정보 부족을 최종 검증 완화로 연결하지 않는다.
- 불가 표시가 있더라도 실제로 놓은 파일은 기존 검증으로 최종 판단하고 오류를 안내한다. 브라우저의 파일 열기 같은 기본 동작으로 빠지지 않게 처리한다.
- 여러 파일을 놓았을 때 첫 파일을 사용하는 현재 정책을 유지한다. 사전 안내도 실제 선택 대상과 맞추며, 순서나 대상 정보가 불명확하면 사전 불가로 단정하지 않는다. 링크·텍스트 드래그를 파일 선택으로 처리하거나 기존 영상을 지우는 근거로 삼지 않는다.
- 이번 검증은 파일 형식에 관한 것이다. 용량 초과는 기존 업로드 오류 경로에서 처리하며, 드래그 중 용량 검증을 추가하지 않는다.

### 거부한 파일과 기존 선택

- 새 파일은 검증 통과 후 현재 선택을 교체한다. 정상 파일을 놓으면 이전 파일 입력 오류를 해제하고 기존 정상 선택 경로로 이어간다.
- 새 파일이 유효하지 않으면 기존 선택 영상·파일 정보·처리 방식을 보존한다. 선택이 없었다면 빈 상태를 유지한다. 방금 놓은 파일이 거부되었음을 명확히 안내한다.
- 유지된 정상 영상의 제출 가능 여부는 해당 영상과 기존 요청 상태를 기준으로 계산한다. 거부한 새 파일을 현재 선택으로 취급해 정상 영상 자체를 무효화하지 않는다. 기존 선택이 없으면 제출 불가 상태를 유지한다.
- 단순 진입·이탈·취소는 선택 영상, 기존 오류, 업로드 관련 상태를 바꾸지 않는다.

## Testing Decisions

주 검증 경계는 기존 자막 추출 화면의 브라우저 테스트다. 실제 화면에서 입력하고 표시·선택 결과를 관찰한다. 드래그 카운터, 내부 상태명, 특정 스타일 클래스의 존재만 확인하는 테스트를 완료 근거로 삼지 않는다.

- 기존 요청·내역 브라우저 검증에는 자막 파일 선택 버튼의 Enter·Space 입력, 드래그 기본 동작 차단, 세 가지 지원 형식 놓기, 비지원 파일 오류 표시가 있다. 이 시나리오를 확장한다. 새로운 별도 테스트 환경은 만들지 않는다.
- 정상 형식과 불명확한 형식의 진입 시 위치 안내, 명확한 비지원 형식의 오류색·아이콘·문구, 내부 요소 간 이동 시 표시 유지, 이탈·놓기·취소 후 복원을 확인한다.
- 드래그 중에는 실제 파일 목록을 읽을 수 없고 형식 정보만 있는 조건을 재현한다. 합성 이벤트에서 완전한 파일 정보를 제공해 사전 판정이 실제보다 쉽게 통과하지 않게 한다.
- 정상 영상이 있는 경우와 없는 경우에 잘못된 파일을 놓는다. 기존 선택·처리 방식 보존 또는 빈 상태 유지, 새 오류 안내, 현재 선택에 맞는 제출 가능 상태를 확인한다.
- 드래그 중 정보가 없었지만 놓은 뒤 거부되는 경우, 지원 MIME이지만 확장자가 잘못된 경우, 실제 파일 MIME이 비어 있는 경우를 포함한다. 최종 허용 목록은 완화하지 않는다.
- 정상 파일을 다시 놓으면 선택이 교체되고 이전 파일 입력 오류가 해제되는지 확인한다. 복수 파일은 기존 첫 파일 정책과 표시가 일치하는지 확인한다.
- 기존 오류가 있는 상태에서 진입·이탈을 반복해 오류 문구 보존과 오류 테두리 복원을 확인한다.
- 기존 테스트의 “정상 선택 후 잘못된 파일을 놓으면 제출 불가” 기대값은 선택 보존 계약에 맞춰 수정한다. 파일 이름·메타 정보와 제출 대상이 보존된 영상으로 일치하는지 화면 경계에서 확인한다.
- 기존 화면 마크업 테스트와 파일 검증 단위 테스트는 기존 계약 회귀를 보완한다. 정적 마크업만으로 드래그 동작이나 실제 포커스 이동이 검증됐다고 기록하지 않는다.
- 라이트·다크 테마, 좁은 화면에서 상태 전환에 따른 박스 크기 변화·문구 넘침·주변 배치 이동을 확인한다. 클릭·Enter·Space 파일 선택과 실제 포커스 표시를 회귀 확인한다.
- 구현 후 최신 Web 정적 검사, 단위 테스트, 기존 브라우저 테스트를 실행하고 결과를 구분해 기록한다.
- 실제 운영체제 파일 관리자에서 브라우저로 지원 파일·비지원 파일을 드래그한다. 진입, 내부 이동, 이탈, 취소, 놓기, 기존 선택 보존을 확인하고 운영체제·브라우저와 결과를 기록한다. 합성 이벤트 검증을 실제 파일 드래그 성공으로 대체하지 않는다. 실행하지 못한 환경은 미검증으로 남긴다.

## Out of Scope

- 구현 코드 작성, 구현 티켓 분할, 커밋·푸시·배포는 이 스펙 작성 작업에 포함하지 않는다.
- 페이지 전체를 덮는 드롭 영역, 새로운 업로드 화면, 과장된 애니메이션.
- 지원 확장자·MIME 목록 변경, 영상 내용 검사, 용량 사전 판정, 코덱·추출 성공 보장.
- 복수 파일 일괄 처리, 디렉터리 업로드, 링크·텍스트로 자막 원본 입력.
- 파일 선택 대화상자의 오류·취소 정책 재설계.
- 서버·worker·저장소·접수증·추출 요청 생명주기 변경, Chrome 확장 프로그램 변경.

## Further Notes

- 사용자가 Q1–Q6과 최종 요약을 확정하고 새 스펙 작성을 요청한 내용을 반영했다. 구현 준비 상태이며, 구현 또는 실환경 검증 완료를 의미하지 않는다.
- 기존 코드 조사와 브라우저 문서 확인을 근거로 작성했다. 이 스펙 작성 중 실제 드래그 시험은 수행하지 않았다.
- 브라우저는 드래그 중 항목의 형식 정보를 제공할 수 있지만, 실제 파일 목록은 놓기 전 보호된다. 정보가 부족할 때 위치 안내로 처리하는 이유다. 참고: [DataTransferItem.type](https://developer.mozilla.org/en-US/docs/Web/API/DataTransferItem/type), [DataTransfer.files](https://developer.mozilla.org/en-US/docs/Web/API/DataTransfer/files).
- 개인 사용 단계와 기존 디자인 계약을 유지한다. 새 서버 계약이나 공개 서비스 기능을 도입하지 않는다.
