# 실제 5시간 31분 영상: 640MiB 단기 대응 검증

2026-09-09에 사용자가 제공한 원본 전체를 실제 FFmpeg와 Whisper로 처리했다. **이 파일은 640MiB 한도로 상향하면 자막 생성까지 완료된다.** 제품 설정과 데이터베이스 작업 상태는 변경하지 않았다.

- Linux ARM64 worker 이미지 `mytube-extract-worker:latest`에 준비된 whisper.cpp Linux 빌드와 `ggml-base.en.bin`을 연결했다.

## 크기 제한과 결과 검증

실제 추출된 WAV를 현재 worker 크기 검사 함수에 넣어 두 한도를 비교했다.

```text
536870912 bytes → AUDIO_TOO_LARGE
subtitle audio is too large: 635661494 bytes
671088640 bytes → PASS
```

전체 인식은 `FULL_PASS`로 종료됐다. 당시 자막 구조 검증 도구도 통과했으며 결과는 다음과 같다.

```json
{"cue_count":4354,"first_start":0.0,"last_end":19864.3,"source_duration":19864.421,"errors":[],"pass":true}
```

검사한 항목은 자막 파일 존재, 연속 번호, 시간 형식, 시작보다 늦은 종료, 원본 범위 안의 시각, 시작 시각 정렬, 원본 마지막 30초 도달 여부다. 최종 자막이 원본 끝 0.121초 전까지 도달한다. 전문 용어 인식 정확도나 전 문장 누락 여부를 사람이 교정한 검증은 아니다.

## 단기 대응 판단

**이번 파일과 `base_en` 모델에 대해서는 `SUBTITLE_AUDIO_MAX_BYTES=671088640` 상향이 유효하다.** 단순 크기 검사뿐 아니라 실제 전체 인식과 자막 파일 생성을 확인했다.

운영 적용 시 확인할 점:

- 이 테스트는 5GiB 메모리 한도에서 성공했다. 운영 worker도 이번 최대 관측값 3.92GiB와 다른 프로세스·캐시를 감당할 여유가 있는지 확인한다. 4GiB만으로도 안전하다고 일반화하지 않는다.
- 원본과 추출 WAV만 합쳐 약 1.31GiB의 임시 디스크 공간이 필요하며 다른 파일·작업을 위한 여유도 필요하다.
- 전체 처리에 약 26분이 걸렸으므로 현재 단일 worker에서 다른 요청이 그동안 대기할 수 있다. 더 느린 운영 머신에서는 시간이 늘어난다.
- `small_en` 모델과 더 긴 영상은 이번 실험 범위 밖이다. 640MiB는 이번 파일에 약 33.79MiB의 여유만 준다.
- 1시간 복구 기준보다 짧게 끝났지만 그 설정이 실행 프로세스 강제 종료 타이머가 되는 것은 아니다.
- 설정 변경 후 기존 실패 작업은 자동 재실행되지 않는다. 새 요청 또는 명시적인 재시도 절차가 필요하다.
