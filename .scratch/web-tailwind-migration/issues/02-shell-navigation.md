# 02: 공통 화면 구조와 내비게이션 전환

Status: ready-for-human

**What to build:** 영상·자막 요청, 요청 내역, 설정 사이를 이동할 때 공통 헤더·본문·하단 내비게이션과 사용 안내가 같은 배치와 조작을 유지한다.

**Blocked by:** 01: Tailwind 연결과 기존 스타일 공존 기반

## 완료 조건

- [x] 공통 헤더·본문 컨테이너·제목·아이콘·주요 내비게이션·하단 탭·사용 안내의 일반 스타일을 유틸리티로 옮긴다. 01에서 옮긴 요소는 재전환하지 않는다.
- [x] 네 주요 화면에서 현재 위치·비활성 표시와 링크 이동이 유지되고 본문 최대 폭·좌우 정렬·하단 여유 공간이 동일하다.
- [x] 사용 안내와 더보기의 기존 펼침·닫힘, 키보드 조작, 닫힌 뒤 포커스 처리를 실제 브라우저에서 확인한다.
- [x] 라이트·다크와 합의한 세 화면 크기에서 공통 영역을 비교하고 기존 반응형 전환점 직전·직후에 탭·헤더 전환과 가로 넘침을 확인한다.
- [ ] 글자 200% 확대 시 주요 이동·안내 요소가 잘리지 않으며 기존 포커스 표시와 터치 영역을 유지한다.
- [x] 다른 화면에서 아직 사용하는 공통 선택자는 유지한다. 전환된 영역에서의 이전 규칙 영향과 후속 소비자를 기록한다.

## 공통 보존·검증 조건

- [x] 최신 디자인·동작 계약과 별도 작업 변경을 보존한다. Chrome 확장 프로그램·Popup, 서버 요청·응답·저장 정책 및 제품 기능은 변경하지 않는다.
- [x] 변경 전후 동일한 브라우저·폰트·fixture·화면 상태를 사용하고 변동 요소를 통제한다. 해당 영역의 시각·키보드·동작 회귀를 이 티켓에서 해결한다.
- [x] 기존 브라우저 사용자 동작 검증과 관련 단위 검사를 재사용한다. 마지막 관련 변경 이후 타입 검사·전체 단위 테스트·배포용 빌드·기존 브라우저 smoke 결과와 미검증 경계를 기록한다.

## 구현 및 검증 기록 (2026-09-07)

- 공통 shell, hero, 아이콘, 데스크톱·모바일 내비게이션, 사용 안내 disclosure의 일반 배치·간격·색상·반응형 규칙을 Tailwind 유틸리티로 이동했다. `app-shell`, `workspace`, `app-header`, `usage-guide`, `primary-navigation`, `bottom-tab-bar` 등 기존 선택자는 유지했다.
- CSS에 남긴 규칙은 native `details` 표식/chevron과 safe-area inset처럼 유틸리티로 대체하기 어려운 브라우저 특수 효과, 토큰·기본 스타일, 다른 화면 소비자 규칙으로 한정했다.
- 포커스·Escape·바깥 클릭·포커스 반환과 링크/비활성/현재 위치 동작을 Chromium smoke에서 확인했다. 라이트·다크와 `320, 390, 560, 561, 640, 800, 820, 821, 1280px` 폭에서 내비게이션 전환과 가로 넘침을 확인했다. `640px`은 1280px CSS viewport를 200% 확대한 환경의 유효 폭을 대신하는 보조 검증이다.
- `pnpm --filter web run lint`, `pnpm test`, `pnpm --filter web run test:browser`를 최신 변경 뒤 통과했다. 전체 테스트는 12개 태스크 성공, 웹은 18개 테스트 파일/135개 테스트 통과다.
- 실제 브라우저 UI의 200% text zoom, 실기기 safe-area/touch, screen reader는 이 실행에서 증명하지 못했으므로 `ready-for-human`으로 남긴다. 해당 확인 전에는 200% 완료 조건을 성공으로 주장하지 않는다.

## 범위 경계

요청 준비·진행·결과의 내부 표시는 03~07에 남긴다.

이 티켓은 확정된 Web 앱 Tailwind CSS 전환 스펙을 따른다. 상태 표시는 작업 준비 상태이며, 티켓 게시 자체가 코드 구현 착수를 뜻하지 않는다.
