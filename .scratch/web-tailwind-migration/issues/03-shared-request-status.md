# 03: 공통 요청 준비·상태 안내 전환

Status: done (2026-09-07)

**What to build:** 영상·자막 요청의 준비 여부와 공통 단계·오류 안내를 기존처럼 이해하고 조작할 수 있다.

**Blocked by:** 02: 공통 화면 구조와 내비게이션 전환

## 완료 조건

- [x] 공통 준비 상태 패널, 처리기 상태 안내, 요청 단계 표시, 오류 상세 펼침과 공통 오류 경계 표시를 유틸리티로 전환한다.
- [x] 확인 중·준비 완료·확인 실패·작업 처리기 미가용을 기존 응답 fixture로 재현하고 각 상태의 문구·조작 가능 여부·표시 위계를 보존한다.
- [x] 준비된 입력 화면이 백그라운드 상태 확인 중 불필요하게 사라지거나 입력값을 잃지 않는다. 완료된 확인 결과에 따른 기존 전환을 유지한다.
- [x] 오류 상세의 펼침·닫힘·키보드 포커스와 재확인 동작을 기존처럼 유지하며 상태 공지와 반복 공지 억제 동작을 바꾸지 않는다.
- [x] 영상·자막 양쪽에서 공통 표시를 라이트·다크 및 세 화면 크기로 비교한다. 초기·실패 상태도 배포용 빌드에서 스타일이 누락되지 않는다.
- [x] 공통 영역만 소유하고 영상·자막 고유 입력·결과 내부는 후속 티켓에 남긴다. 공유 규칙을 제거하기 전에 양쪽 소비자를 확인한다.

## 공통 보존·검증 조건

- [x] 최신 디자인·동작 계약과 별도 작업 변경을 보존한다. Chrome 확장 프로그램·Popup, 서버 요청·응답·저장 정책 및 제품 기능은 변경하지 않는다.
- [x] 변경 전후 동일한 브라우저·폰트·fixture·화면 상태를 사용하고 변동 요소를 통제한다. 해당 영역의 시각·키보드·동작 회귀를 이 티켓에서 해결한다.
- [x] 기존 브라우저 사용자 동작 검증과 관련 단위 검사를 재사용한다. 마지막 관련 변경 이후 타입 검사·전체 단위 테스트·배포용 빌드·기존 브라우저 smoke 결과와 미검증 경계를 기록한다.

## 구현 및 검증 기록 (2026-09-07)

- 공통 `RequestReadinessPanel`, `WorkerHealthStatusNotice`, `RequestFlow`, `ErrorDetailsDisclosure`, `ErrorBoundary`의 일반 layout·간격·색상·위계 스타일을 Tailwind 유틸리티로 이동했다. 기존 semantic class와 `data-*`/ARIA 계약은 유지했다.
- 영상·자막 페이지의 readiness fixture, 백그라운드 확인 중 입력 보존, 완료 전환, 오류 상세 disclosure의 펼침·닫힘·재확인·포커스 및 상태 공지 로직은 변경하지 않았다. 페이지 고유 입력·결과 내부 스타일은 후속 티켓 범위로 남겼다.
- 전환한 규칙을 `apps/web/src/styles/global.css`에서 제거하고, `phase-panel`, `console-panel`, 기본 버튼과 같은 다른 소비자의 공통 규칙은 유지했다. 요청 단계의 `ol` 기본 패딩을 `p-0`으로 명시해 320px 이력 화면의 가로 넘침 회귀를 수정했다.
- 전환 전 관련 단위 기준은 4개 파일/28개 테스트 통과였다. 최종 검증은 아래와 같다.
  - `pnpm --filter web run lint`: 통과
  - `pnpm --filter web run test`: 18개 파일/135개 테스트 통과
  - `pnpm --filter web run build`: 통과, `Vite web package verified.`
  - `pnpm test`: 12개 태스크 성공, Web 빌드·테스트 포함
  - `pnpm --filter web run test:browser`: 25개 시나리오와 정적 서버 종료 상태 `ok`
- 동일한 로컬 Chromium fixture에서 영상·자막의 light·dark, `320x844`·`390x844`·`1280x900` 상태를 확인했다. compact/expanded worker 상태, 준비 중·준비 완료·실패·미가용 상태, 요청 단계, 오류 상세 및 재확인 control의 computed layout과 스타일이 배포용 CSS에 포함되며, 문서 가로 넘침이 없음을 측정했다.

## 검증 경계

로컬 fixture·정적 서버·Chromium·단위 검사·배포용 빌드는 Tailwind 생성물과 로컬 Web 동작만 증명한다. 실제 API·작업 처리기·YouTube 제공자·R2·운영 배포·물리 모바일 기기·실제 화면 낭독기는 검증하지 않았다.

## 범위 경계

요청 생명주기 모델과 서버 응답 변환을 변경하지 않는다.

이 티켓은 확정된 Web 앱 Tailwind CSS 전환 스펙을 따른다. 상태 표시는 작업 준비 상태이며, 티켓 게시 자체가 코드 구현 착수를 뜻하지 않는다.
