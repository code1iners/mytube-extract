# 04: 영상 추출 입력·옵션 전환

Status: done (2026-09-07)

**What to build:** 사용자가 영상 주소와 추출 옵션을 기존처럼 입력하고 추출 요청을 접수할 수 있다.

**Blocked by:** 03: 공통 요청 준비·상태 안내 전환

## 완료 조건

- [x] 주소 입력·지우기, 추출 형식·품질 선택, 입력 피드백, 요청 버튼·비활성 사유의 일반 스타일을 유틸리티로 옮긴다.
- [x] 비어 있음·유효 입력·잘못된 입력, 각 형식·품질의 선택 상태, 활성·비활성·포커스 상태의 외형과 접근 가능한 이름을 보존한다.
- [x] 주소 입력 → 옵션 선택 → 제출을 브라우저에서 실행하여 기존 요청 내용으로 접수되고 중복 제출 억제가 유지됨을 확인한다.
- [x] 입력·선택값 유지와 초기 선호 복원, 지우기 동작 및 기존 키보드 탐색을 보존한다. 제거된 단축키를 복원하지 않는다.
- [x] 라이트·다크 및 세 화면 크기에서 입력 순서·너비·간격·버튼 터치 영역과 하단 내비게이션 겹침 여부를 비교한다.
- [x] 접수 이후 상태는 기존 구현과 공존하여 계속 동작한다. 공통 버튼 등 미전환 소비자가 있는 규칙은 남겨 두고 기록한다.

## 공통 보존·검증 조건

- [x] 최신 디자인·동작 계약과 별도 작업 변경을 보존한다. Chrome 확장 프로그램·Popup, 서버 요청·응답·저장 정책 및 제품 기능은 변경하지 않는다.
- [x] 변경 전후 동일한 브라우저·폰트·fixture·화면 상태를 사용하고 변동 요소를 통제한다. 해당 영역의 시각·키보드·동작 회귀를 이 티켓에서 해결한다.
- [x] 기존 브라우저 사용자 동작 검증과 관련 단위 검사를 재사용한다. 마지막 관련 변경 이후 타입 검사·전체 단위 테스트·배포용 빌드·기존 브라우저 smoke 결과와 미검증 경계를 기록한다.

## 범위 경계

접수 이후 고유 상태 화면과 결과 스타일은 05가 담당한다.

이 티켓은 확정된 Web 앱 Tailwind CSS 전환 스펙을 따른다. 상태 표시는 작업 준비 상태이며, 티켓 게시 자체가 코드 구현 착수를 뜻하지 않는다.

## 구현 및 검증 기록 (2026-09-07)

- `/video` 요청 단계의 panel·URL 입력·지우기·형식/품질 선택·검증 피드백·제출 button·비활성 사유를 Tailwind utility class로 전환했다. 기존 semantic class와 접근 가능한 이름·radio 구조·폼 동작은 유지했다.
- 기존 global CSS의 영상 입력 규칙은 제거하고 아직 이전 스타일을 소비하는 자막 입력 규칙만 `.subtitle-request-panel` 아래에 보존했다. 선택 상태 우선순위와 320px 자막 1열 규칙이 유지되도록 scope specificity를 조정했다.
- URL 지우기·형식/품질 전환·선호 복원·요청 접수·중복 제출 억제·접수 이후 lifecycle은 기존 구현을 재사용했다. 제거된 U/F 단축키는 복원하지 않았다.
- 라이트·다크 및 `320x844`·`390x844`·`1280x900`에서 URL 표면, 선택 상태, disabled/enabled button, 오류 border, focus ring, 터치 영역, 하단 navigation 여유를 computed style과 layout으로 확인했다.
- 검증 결과:
  - `pnpm --filter web run lint`: 통과
  - `pnpm --filter web run test`: 18개 파일 / 135개 테스트 통과
  - `pnpm --filter web run build`: 통과, `Vite web package verified.`
  - `pnpm --filter web run test:browser`: 전체 시나리오와 정적 서버 종료 상태 `ok`
- 위 결과는 로컬 fixture·배포용 CSS·Chromium 범위의 증거다. 실제 API·worker·YouTube provider·R2·운영 배포, 물리 기기 safe-area/브라우저 chrome, 실제 화면 낭독기는 검증하지 않았다.
