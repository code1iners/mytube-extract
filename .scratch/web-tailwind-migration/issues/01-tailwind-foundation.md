# 01: Tailwind 연결과 기존 스타일 공존 기반

Status: ready-for-human

**What to build:** 기존 Web 앱의 모양과 동작을 유지하면서 Tailwind로 작성한 작은 공통 표시 요소가 기존 화면 안에서 정상 표시된다. 후속 화면 전환은 이 공존 기반에서 시작할 수 있다.

**Blocked by:** 없음 (즉시 시작 가능)

## 완료 조건

- [x] 착수 시 최신 코드·디자인 계약·별도 작업 변경을 확인하고, 네 주요 화면의 라이트·다크 및 320×844·390×844·1280×900 기준 화면을 스타일 변경 전에 확보한다. 기존 검사 실패와 기준 버전을 기록한다.
- [x] 현재 빌드 환경에 호환되는 Tailwind 연결 방식을 확인하고 의존성·잠금 정보를 고정한다. 새 컴포넌트 라이브러리나 별도 테마 모델을 도입하지 않는다.
- [x] 기존 역할별 디자인 토큰과 테마 상태를 유틸리티에서 사용할 수 있게 연결한다. 색상·폰트·간격 등 기존 값을 Tailwind 기본값에 맞춰 바꾸지 않는다.
- [x] 작은 공통 표시 요소 하나를 실제 유틸리티로 전환하고 라이트·다크에서 기존 표시를 유지한다. 선택한 요소와 책임을 기록하여 02·03에서 중복 전환하지 않게 한다.
- [x] 기본 스타일 초기화와 기존 전역 선택자의 우선순위가 미전환 화면의 버튼·입력·제목·테두리를 바꾸지 않는다. 미전환 화면 규칙을 조기에 삭제하지 않는다.
- [x] 시스템 테마 적용과 저장된 라이트·다크 선호 복원이 기존처럼 동작하고 배포용 빌드에서도 전환한 요소의 스타일이 생성된다.
- [x] 기존 브라우저 검증 방식을 재사용하고 스타일 문자열만 검사하는 새 테스트 계층을 만들지 않는다. 회귀가 있으면 기반 단계에서 해결한다.

## 공통 보존·검증 조건

- [ ] 최신 디자인·동작 계약과 별도 작업 변경을 보존한다. Chrome 확장 프로그램·Popup, 서버 요청·응답·저장 정책 및 제품 기능은 변경하지 않는다.
- [ ] 변경 전후 동일한 브라우저·폰트·fixture·화면 상태를 사용하고 변동 요소를 통제한다. 해당 영역의 시각·키보드·동작 회귀를 이 티켓에서 해결한다.
- [ ] 기존 브라우저 사용자 동작 검증과 관련 단위 검사를 재사용한다. 마지막 관련 변경 이후 타입 검사·전체 단위 테스트·배포용 빌드·기존 브라우저 smoke 결과와 미검증 경계를 기록한다.

## 범위 경계

기반 연결과 작은 실제 적용만 담당한다. 공통 화면 구조 전체 전환은 02, 요청 공통 안내는 03이 담당한다.

이 티켓은 확정된 Web 앱 Tailwind CSS 전환 스펙을 따른다.
