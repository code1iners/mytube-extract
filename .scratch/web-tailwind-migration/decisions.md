# 웹 Tailwind 전환 논의

상태: Q1~Q5 및 전체 전환 방침을 사용자가 최종 확정했다. 구현 없이 스펙을 먼저 작성하도록 요청했다.

## 확정된 결정

- Q1: `apps/web`만 전환한다. Chrome 확장 팝업은 이번 범위에서 제외한다.
- Q2: 레이아웃·간격·색상·반응형 스타일은 Tailwind 유틸리티 클래스로 작성한다. 전역 스타일에는 디자인 토큰·폰트·기본 규칙·필요한 특수 효과만 남긴다. 기존 클래스에 `@apply`만 붙이는 방식으로 전환하지 않는다.
- Q3: 현재 디자인과 동작을 유지한다. 색상·다크 모드·반응형 배치·접근성·사용자 흐름을 보존하며, 디자인 개선은 포함하지 않는다.
- Q4: 공통 기반 → 영상·자막 요청 → 기록·설정 순서로 나누어 전환하고 단계마다 검증한다. 중간 단계에서는 기존 스타일과 함께 사용하되, 완료 시에는 이전 화면 스타일을 제거한다.
- Q5: 기존 자동 검사와 함께 주요 화면·상태를 밝은·어두운 테마 및 모바일·데스크톱 폭에서 전환 전후 비교한다. 키보드 조작·포커스 표시·요청 및 기록 흐름을 확인하며, 실행하지 못한 실제 환경 검증은 별도로 명시한다.

## 현재 코드에서 확인한 사실

- `apps/web/src/main.tsx`에서 `styles/global.css`를 가져온다.
- 최초 조사 당시 `apps/web/src/styles/global.css`는 2,160줄이며 디자인 토큰과 화면별 스타일, 반응형 규칙을 함께 정의했다. 구현 착수 시 최신 상태를 다시 확인한다.
- 현재 웹 패키지에는 Tailwind 의존성이 없다.
- 시각적 계약의 기준은 `docs/DESIGN.md`이다.

## 최종 확인과 착수 조건

- Q1~Q5를 묶은 전체 전환 방침은 사용자 최종 확인을 받았다.
- 구현 착수 시 최신 코드와 `docs/DESIGN.md`를 다시 확인하여 전환 전 기준을 확보한다. 현재 작업 트리에 존재하는 별도 변경은 보존한다.

[구현 명세](./spec.md)를 `ready-for-agent` 상태로 작성했다. 코드 구현과 작업 티켓 작성은 진행하지 않았다.
