# 07: 영상·오디오 즉시 다시 요청

Status: ready-for-agent

**What to build:** 사용자가 실패·만료된 영상 또는 오디오 항목의 `다시 요청`을 한 번 누르면 이전 원본·형식·품질로 새 요청을 접수한다. 내역에 머무르며 진행을 확인하고, 작성 중인 다른 입력과 기존 내역을 유지한다.

**Blocked by:** 05: 자막 입력 보존과 새 요청; 06: 요청 내역 목록·상세·삭제.

**기준:** Web 최소 구성 재설계 명세. 관련 사용자 요구사항: 25, 26, 27, 28, 34, 37, 40, 43, 44, 45, 46, 48, 54.

**착수 조건:** 현재 승인은 티켓 발행까지다. 제품 구현은 사용자의 별도 구현 요청 후 시작한다.

## 완료 조건

- [ ] 정상 조회된 실패·만료 항목의 원본 주소·형식·품질로 즉시 접수를 시도한다. 입력 화면 이동·별도 확인창·추가 제출 없이 실행하며 준비 확인과 입력 검증은 유지한다.
- [ ] 원본은 서버가 제공하는 정규화된 주소를 사용한다. 요청 상태를 조회하지 못해 조건이 없으면 임의로 실행하지 않고 조회 복구를 제공한다. 404에서는 기존 내역 정리 규칙을 따른다.
- [ ] 내역 화면에서 요청을 시작한 위치에 접수 중 상태·필요한 취소·실패 안내를 제공한다. 빠른 반복 클릭과 다른 항목의 재요청으로 중복 접수가 생기지 않는다.
- [ ] 접수 중 이동 잠금과 접수 전 취소를 기존 추출 요청 생명주기에 연결한다. 취소·실패 뒤 조작 가능 상태를 되찾고, 늦은 성공 응답이 오면 이미 생성된 작업의 접수증을 보존한다.
- [ ] 기존 영상 어댑터와 추출 요청 생명주기를 재사용한다. 목록 각 항목마다 준비 확인·접수 제어를 반복 생성하거나 별도 생명주기를 복제하지 않는다. 08이 자막 요청에도 연결할 수 있는 내역의 공통 접수 제어를 마련한다.
- [ ] 영상 주소·형식·품질과 자막 파일·처리 방식의 작성 중 초안을 모두 유지한다. 내역 재요청용 입력을 두 추출 화면의 입력에 주입하지 않는다.
- [ ] 서버 접수가 실제 확인됐을 때만 재사용한 형식·품질을 이후 기본값으로 기억한다. 내역 조회·접수 실패·접수 전 취소에서는 기본값을 바꾸지 않으며, 작성 중 초안의 선택은 그대로 둔다.
- [ ] 초안을 다시 열어도 복원 효과가 재요청 성공으로 갱신된 기본값을 되돌리지 않는다. 저장 불가 환경에서는 현재 세션을 유지하고 저장 지속성을 과장하지 않는다.
- [ ] 접수 성공 시 별도 식별자의 새 요청을 목록에 반영한다. 원래 항목의 상태·시각·접수증을 덮어쓰지 않으며, 기존 최신 20건 보존 규칙을 유지한다.
- [ ] 접수 후 준비 확인 오류가 작업 상태를 덮어쓰지 않는다. 접수증 저장 실패에서도 서버 요청을 실패로 바꾸지 않고 현재 세션의 내역 접근을 제공한다.
- [ ] 재요청·취소·오류 복구의 이름·상태 공지·키보드 포커스와 명세의 대비·44×44px 조작 영역을 확인한다.
- [ ] 기존 브라우저 시나리오로 영상·오디오 각각의 실패·만료 재요청 조건, 한 번의 생성, 새 내역, 화면 유지, 두 종류 초안 보호, 기본값 갱신·미갱신을 검증한다.
- [ ] 기존 생명주기 공개 인터페이스 검증으로 취소와 늦은 성공·저장 실패·준비 오류 우선순위를 필요한 만큼 보강한다. 새 서버 명령·서버 작업 취소를 도입하지 않는다.
- [ ] 마지막 변경 이후 관련 정적 검사·자동 테스트·빌드·브라우저 결과를 기록하고 영상·오디오 다시 요청과 기본값 저장 설명을 갱신한다.

## 후속 연결

05는 04에서 만든 영상·오디오 보관도 포함하므로 두 입력의 보존이 선행된다. 08에서 파일 재선택과 자막 업로드를 같은 내역 접수 제어에 연결하고 종류 사이의 중복 실행도 검증한다.
