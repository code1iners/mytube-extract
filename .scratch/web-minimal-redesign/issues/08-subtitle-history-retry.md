# 08: 자막 파일 재선택으로 다시 요청

Status: ready-for-agent

**What to build:** 사용자가 실패·만료된 자막 항목에서 `다시 요청`을 누르고 원본 파일만 다시 선택하면 이전 처리 방식으로 업로드와 새 접수가 시작된다. 작성 중인 입력을 유지하면서 파일 선택 취소·오류·영상과 자막 사이의 중복 실행을 처리한다.

**Blocked by:** 07: 영상·오디오 즉시 다시 요청 (내역의 접수·취소·중복 방지 처리 재사용).

**기준:** Web 최소 구성 재설계 명세. 관련 사용자 요구사항: 25, 26, 27, 28, 34, 37, 41, 42, 43, 44, 45, 46, 48, 54.

**착수 조건:** 현재 승인은 티켓 발행까지다. 제품 구현은 사용자의 별도 구현 요청 후 시작한다.

## 완료 조건

- [ ] 정상 조회된 실패·만료 자막 항목에서 파일 선택을 열고, 유효한 파일을 고르면 이전 처리 방식으로 기존 업로드·접수 절차를 실행한다. 입력 화면 이동·별도 확인창·추가 제출을 요구하지 않는다.
- [ ] 파일 선택 취소나 파일 검증 실패에서는 업로드·접수·기본값 갱신이 일어나지 않는다. 작성 중인 자막 파일을 재요청 파일로 자동 사용하지 않는다.
- [ ] 이전 처리 방식을 상태 응답에서 확보하지 못하면 임의의 기본 모델로 실행하지 않고 조회 복구를 제공한다. 기존 404 내역 정리 규칙을 유지한다.
- [ ] 준비 확인과 파일 검증, 업로드 시작·부분 전송·완료·실패 정리는 기존 자막 어댑터와 추출 요청 생명주기를 사용한다. 내역 항목이 새 통신 절차나 독립 생명주기를 만들지 않는다.
- [ ] 07의 내역 접수 제어에 자막을 연결한다. 영상·오디오·자막의 빠른 반복 실행이나 다른 항목 실행으로 동시에 중복 접수하지 않으며, 접수 중에는 기존 이동 잠금을 적용한다.
- [ ] 내역 화면에서 업로드·접수 상태와 필요한 취소·실패 안내를 확인한다. 실제 확인 가능한 진행률만 사용하고, 완료 후에는 결과 다운로드를 제공한다.
- [ ] 파일 선택 취소·접수 전 취소·업로드 또는 접수 실패 후 기존 항목과 두 추출 화면의 작성 중 원본·선택값을 유지한다. 취소와 늦은 성공의 경쟁에서는 생성된 작업의 접수증을 보존한다.
- [ ] 실제 접수 성공 때만 이전 처리 방식을 이후 기본값으로 기억한다. 작성 중 자막 초안의 파일·선택값은 그대로 두고, 초안 복원으로 갱신된 기본값을 덮어쓰지 않는다.
- [ ] 새 요청을 별도 접수증과 식별자로 추적하고 원래 항목을 덮어쓰지 않는다. 기존 최신 20건·다른 탭 내역 반영과 저장 실패 시 현재 세션 접근을 유지한다.
- [ ] 접수 후 준비 상태 오류를 이미 접수된 작업 실패로 표시하지 않는다. 서버 작업 취소·이전 작업 재개·자동 재요청을 추가하지 않는다.
- [ ] 파일 선택·오류 복구·취소를 키보드로 사용할 수 있고, 취소·복구 후 보이는 조작에 포커스를 유지한다. 상태 공지와 명세의 대비·44×44px 조작 영역을 확인한다.
- [ ] 기존 브라우저 시나리오로 실패·만료 자막의 파일 재선택, 실제 전송 파일·이전 처리 방식, 선택 취소·잘못된 파일·용량 오류·업로드 실패·정상 접수를 검증한다.
- [ ] 영상·오디오·자막 재요청이 두 종류의 작성 중 초안과 이후 기본값에 미치는 결과를 함께 검증한다. 요청 종류를 바꾸어 반복 클릭해도 중복 생성이 없음을 확인한다.
- [ ] 기존 생명주기·자막 어댑터 공개 인터페이스 검증에서 업로드 취소·정리·늦은 성공·저장 실패를 확인한다. 마지막 변경 이후 관련 정적 검사·자동 테스트·빌드·브라우저 결과를 기록하고 자막 다시 요청 설명을 갱신한다.

## 완료 판단

이 티켓의 완료는 자막 직접 재요청의 완료를 뜻한다. 재설계 전체의 완료는 01~08의 모든 완료 조건을 확인한 뒤 판단하며, 로컬 브라우저 결과를 실제 처리 서비스·물리 기기·화면 낭독기 검증으로 표현하지 않는다.
