# 05: 자막 입력 보존과 새 요청

Status: ready-for-agent

**What to build:** 사용자가 같은 탭에서 메뉴를 오간 뒤에도 실제 선택 파일과 처리 방식을 유지하고 자막 요청을 제출할 수 있게 한다. 새로고침·새 요청·접수 후 복귀와 같은 화면의 오류 복구를 구분한다.

**Blocked by:** 04: 영상·오디오 입력 보존과 새 요청 (공통 입력 보관 방식 재사용).

**기준:** Web 최소 구성 재설계 명세. 관련 사용자 요구사항: 33, 35, 36, 37, 38, 39.

**착수 조건:** 현재 승인은 티켓 발행까지다. 제품 구현은 사용자의 별도 구현 요청 후 시작한다.

## 완료 조건

- [ ] 04의 공통 보관 방식에 자막 파일·처리 방식을 독립적으로 연결한다. 영상·오디오 입력과 자막 입력을 동시에 작성한 뒤 메뉴를 오가도 서로 교체되지 않는다.
- [ ] 메뉴 복귀 후 파일명만 복원하는 대신 실제 전송 가능한 로컬 파일을 유지한다. 기존 분할 업로드 절차가 그 파일을 사용한다.
- [ ] 새로고침하면 원본 파일을 비우고 기억한 처리 방식만 복원한다. 파일이나 파일 내용을 영속 저장하거나 다른 탭으로 동기화하지 않는다.
- [ ] 사용자가 처리 방식을 직접 바꿀 때만 현재 선택과 이후 기본값을 갱신한다. 초안 복원·화면 재진입으로 기억한 기본값을 덮어쓰지 않으며 저장된 선호가 없으면 기존 속도 우선을 사용한다.
- [ ] 완료 후 `새 요청`은 파일을 비우고 해당 화면의 처리 방식을 유지한다. 이미 완료한 작업은 내역에서 계속 확인한다.
- [ ] 접수 후 같은 화면에서는 진행·결과와 오류 복구에 필요한 파일을 유지한다. 다른 메뉴로 이동하고 돌아오면 파일이 빈 새 입력과 기억한 처리 방식을 제공한다.
- [ ] 접수 전 취소·접수 실패·같은 화면의 오류 복구에서 기존 파일·처리 방식을 유지한다. 접수된 작업의 파일을 메뉴 복귀 시 미제출 초안으로 되살리지 않는다.
- [ ] 파일 변경·지우기가 현재 자막 초안에 반영되며, 잘못된 새 드롭으로 기존 유효 파일이나 다른 종류의 초안을 잃지 않는다.
- [ ] 저장 불가 환경에서 현재 파일·선택으로 작업할 수 있다. 기존 접수 중 이동 잠금·업로드 취소·늦은 접수 성공·접수증 저장 실패 계약을 유지한다.
- [ ] 기존 브라우저 시나리오로 파일 선택 → 다른 메뉴 → 복귀 → 실제 업로드의 파일과 처리 방식을 검증한다. 영상·자막 동시 초안, 새로고침, 완료 후 새 요청, 접수 후 복귀, 취소·오류 복구를 포함한다.
- [ ] 마지막 변경 이후 관련 정적 검사·자동 테스트·빌드·브라우저 결과를 기록하고 자막 입력 수명·새 요청 설명을 갱신한다.

## 후속 연결

파일 선택 영역의 시각 구성은 03이 담당한다. 07·08은 이 티켓까지 완성된 두 종류의 입력 보존을 사용하며, 내역 재요청용 입력을 작성 중 초안과 구분한다.
