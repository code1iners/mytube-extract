# 04: 영상·오디오 입력 보존과 새 요청

Status: done (2026-10-03, 로컬 구현·검증 완료)

**What to build:** 사용자가 같은 탭에서 메뉴를 오가도 작성 중인 영상 주소·형식·품질을 이어서 사용하도록 한다. 새로고침, 완료 후 새 요청, 접수 후 메뉴 복귀가 명세의 서로 다른 초기화 규칙을 따르게 한다.

**Blocked by:** 없음 (선행 티켓 없음).

**기준:** Web 최소 구성 재설계 명세. 관련 사용자 요구사항: 35, 36, 37, 38, 39.

**착수 조건:** 현재 승인은 티켓 발행까지다. 제품 구현은 사용자의 별도 구현 요청 후 시작한다.

## 완료 조건

- [x] 미제출 주소·형식·품질은 같은 탭에서 앱 메뉴를 이동하고 돌아와도 그대로 유지된다. 입력 검증과 포커스는 해당 화면이 담당하고 메뉴 전환보다 오래 유지할 입력만 공통 메모리 보관 책임으로 분리한다.
- [x] 새로고침하면 원본 주소를 비우고 브라우저에 기억한 형식·품질만 복원한다. 원본 주소를 영속 저장하거나 다른 탭으로 동기화하지 않는다.
- [x] 직접 형식·품질을 바꿀 때 현재 선택과 이후 기본값을 갱신한다. 초안 복원·화면 재진입만으로 저장 효과가 실행되어 기억한 기본값을 덮어쓰지 않는다.
- [x] 저장된 선호가 없을 때 오디오 320 kbps를 유지한다. 형식 변경 시 비디오 1080p·오디오 320 kbps를 사용하는 기존 규칙을 유지한다. kbps는 kilobits per second, 초당 데이터 전송량이다.
- [x] 완료 후 `새 요청`은 주소를 비우고 해당 화면의 형식·품질을 유지한다. 완료된 작업은 내역에서 계속 확인할 수 있다.
- [x] 접수 후 같은 화면에 머무르면 진행·결과·오류 복구를 이어서 제공한다. 접수된 화면을 떠났다가 돌아오면 원본이 빈 새 입력과 기억한 선택값을 제공한다.
- [x] 접수 전 취소·접수 실패·같은 화면의 오류 복구는 기존 주소·선택을 유지한다. 미제출 입력과 접수된 요청의 복구용 입력을 구분해 메뉴 이동 시 과거 원본을 새 입력에 다시 채우지 않는다.
- [x] 메뉴 이동으로 이미 접수된 작업을 취소하지 않는다. 접수 중 이동 잠금과 늦은 성공 응답의 접수증 보존은 기존 생명주기 계약을 유지한다.
- [x] 저장 불가 환경에서도 현재 메모리의 주소·선택으로 작업할 수 있다. 저장 실패를 서버 요청 실패로 취급하거나 새로고침 후 선택 복원을 보장하지 않는다.
- [x] 공통 보관 방식은 05가 자막 입력을 독립적으로 연결할 수 있게 한다. 영상·오디오의 초안과 이후 기본값을 별도로 다룰 수 있어야 한다.
- [x] 기존 브라우저 시나리오로 메뉴 이동·복귀 후 실제 생성 요청의 주소·형식·품질, 새로고침, 완료 후 새 요청, 접수 후 복귀, 취소·오류 복구를 검증한다. 변경한 선호 저장 규칙은 기존 선호 계약 테스트에서 보강한다.
- [x] 마지막 변경 이후 관련 정적 검사·자동 테스트·빌드·브라우저 결과를 기록하고 영상 입력 수명·새 요청 설명을 갱신한다.

#### 구현

- `request-draft.util.ts`에 탭 메모리의 영상 전용 초안을 분리했다. 원본·선택·접수 여부·입력 버전을 보관하고 검증과 포커스는 영상 화면이 담당한다. 자막은 동일 모듈의 별도 보관 공간으로 확장할 수 있다.
- 미제출 입력은 메뉴 이동 중 유지하며, 접수된 원본은 현재 화면의 복구에만 사용한다. 재진입에서는 기억한 선택과 빈 주소로 시작한다. 완료 후 새 요청은 주소만 비우고 현재 선택을 유지한다.
- 형식·품질은 직접 변경할 때만 저장하며 화면 복원 효과에서는 저장하지 않는다. 이후 기본값이 달라져도 기존 초안의 선택은 유지한다. 저장 실패 시 선택은 메모리에 남으며 새로고침 복원은 보장하지 않는다.
- 직접 입력을 변경하면 새 미제출 버전으로 구분한다. 취소된 이전 요청의 늦은 성공은 제출 버전이 같은 입력에만 접수 표시를 하며, 이후 작성한 초안을 초기화하지 않는다. 접수증과 이동 잠금은 기존 요청 생명주기로 처리한다.
- 영상 화면 설명, Web 구현 문서와 디자인 계약에 입력 수명과 새 요청 규칙을 반영했다.
