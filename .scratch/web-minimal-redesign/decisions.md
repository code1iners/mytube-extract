# Web 최소 구성 재설계 — 합의 기록

상태: 설계 방향·주요 동작·2차 시안 배치 합의 완료 (구현 전)
기록일: 2026-10-02

이 문서는 사용자와 확정한 설계 방향과 주요 동작, 시안에 대한 후속 피드백을 기록한다. 사용자는 2차 시안의 배치를 승인했으며 제품 구현은 후속 작업이다.

## 확정한 범위

- 2026-09-29 화면 점검 인계의 다섯 항목을 모두 다룬다.
- 이번 작업은 설계 합의와 문서화까지 진행한다. 코드는 수정하지 않는다.
- Web의 영상 추출, 자막 추출, 요청 내역과 공통 헤더·내비게이션을 함께 재설계한다.
- 정보의 상시 노출 여부와 사용자 조작 수를 검토한다.
- 모바일에서 입력·선택·요청이 적은 스크롤로 이어지는 구성을 먼저 설계하고, 데스크톱에서도 같은 작업 순서를 유지한다.

## 확정한 시각 방향

사용자는 `minimalist-ui`를 참고해 최대한 단순한 화면과 사용 흐름을 원한다. 스킬의 예시를 모두 도입하는 대신 다음 방향에 합의했다.

| 항목 | 확정한 방향 |
| --- | --- |
| 브랜드 | 로고 아이콘에 기존 브랜드 빨강을 남긴다. |
| 서비스 이름·선택 표시 | 무채색으로 정리한다. |
| 주요 버튼 | 라이트 테마에서는 짙은 회색, 다크 테마에서는 밝은 회색을 사용한다. |
| 상태색 | 오류·완료처럼 의미 전달에 필요한 색만 사용한다. |
| 서체 | Pretendard 단일 서체를 유지한다. |
| 장식 | 장식용 제목 서체, 배경 이미지, 등장 애니메이션을 추가하지 않는다. |
| 여백 | 입력과 선택을 구분할 만큼 사용한다. 큰 빈 공간을 만드는 것을 목표로 삼지 않는다. |
| 카드·설명문 | 실제로 묶어야 하는 정보와 사용자 판단에 필요한 설명에만 사용한다. |

화면 배치는 승인된 2차 시안을 기준으로 한다. 구체적인 색 값, 크기와 간격은 이 방향 및 일반 텍스트·조작 경계·포커스 표시의 접근성 기준에 맞춰 구체화한다.

## 확정한 화면 구성과 동작

| 항목 | 확정한 방향 |
| --- | --- |
| 모바일 내비게이션 | 기존 하단 고정 탭을 유지한다. 상단 메뉴로 통일하자는 제안은 채택하지 않았다. |
| 데스크톱 내비게이션 | 상단 탭 대신 왼쪽에 로고와 영상 추출·자막 추출·요청 내역의 세로 메뉴를 배치한다. 오른쪽 작업 영역에 제목과 입력을 정렬한다. |
| 헤더 보조 메뉴 | 오른쪽 `더보기` 문구·펼침 표시를 가로 점 세 개 `…` 아이콘으로 바꾼다. 버튼의 접근성 이름과 보조 메뉴 기능은 유지한다. |
| 서비스 준비 상태 | 정상 상태의 준비됨·마지막 확인 시각·다시 확인을 숨긴다. 준비 확인 중에도 입력은 가능하게 하고, 제출 버튼 근처에 짧은 상태를 표시한다. 준비되지 않았을 때는 제출을 막고 이유와 다시 확인을 한곳에 표시한다. |
| 단계·진행률 | 공통 `원본 → 추출 → 파일 수령` 단계 표시를 제거한다. 작업 중에는 현재 상태와 실제 진행률을 보여주고, 완료 후에는 결과와 다운로드 동작을 보여준다. 완료된 요청의 100% 막대는 생략한다. |
| 옵션 노출 | 영상의 형식 2개·품질 3개와 자막의 처리 방식 2개를 간결한 선택 영역으로 항상 보여준다. 데스크톱 영상 화면에서는 형식·화질 그룹을 나란히 배치한다. 기술적인 설명만 접어둔다. |
| 파일 선택 | 큰 드래그 영역을 간결한 파일 선택 영역으로 바꾼다. 선택 후에는 같은 위치에 파일명·크기·파일 변경·지우기를 표시한다. 데스크톱의 파일 끌어놓기도 이 영역에서 지원한다. |
| 요청 내역 | 구분선으로 나눈 목록에 제목·형식/품질·요청 시각·상태·주요 행동을 표시한다. 완료 항목의 다운로드와 실패·만료 항목의 다시 요청은 바로 보이며, 상세 설명과 삭제는 펼쳐서 접근한다. |
| 내역의 다시 요청 | 영상·오디오는 `다시 요청`을 누르면 원래 주소·형식·품질로 바로 실행한다. 자막은 원본 파일만 다시 선택하면 이전 처리 방식으로 실행한다. 입력 화면으로 이동하거나 별도 확인창을 띄우지 않으며, 작성 중인 입력은 그대로 유지한다. |

## 확정한 입력 수명과 전환

| 상황 | 확정한 동작 |
| --- | --- |
| 미제출 상태에서 앱 메뉴 이동 | 같은 브라우저 탭에서 앱 메뉴를 오가는 동안 주소·파일·선택값을 유지한다. 돌아오면 작성 중인 입력을 이어서 사용한다. |
| 새로고침 | 원본 주소·파일은 비운다. 브라우저에 기억한 형식·품질·처리 방식만 복원한다. |
| 내역에서 다시 요청 | 작성 중인 주소·파일·선택값을 교체하지 않고 별도의 요청을 시작한다. 자막 파일 선택을 취소하면 요청하지 않는다. |
| 기본 선택값 갱신 | 사용자가 옵션을 직접 변경하거나 재요청이 실제 접수됐을 때 그 선택을 기억한다. 내역 조회·파일 선택 취소·접수 실패로 기본값을 바꾸지 않으며, 기억한 기본값이 바뀌어도 이미 작성 중인 입력의 선택값은 유지한다. |
| 완료 후 새 요청 | 원본 주소·파일을 비우고 형식·품질·처리 방식은 유지한다. |
| 추출 입력 화면에서 접수 후 다른 메뉴로 이동하고 돌아오기 | 원래 추출 탭은 새 요청 입력 화면을 보여준다. 이미 접수된 작업은 요청 내역에서 계속 확인하며, 메뉴 이동으로 취소되지 않는다. 내역에서 재요청한 경우에는 작성 중이던 입력을 유지한다. |

이 합의에서 도출되는 예시는 다음과 같다.

- 영상 주소를 입력한 뒤 내역을 보고 돌아오면, 제출하지 않은 주소와 선택값이 남아 있다.
- 영상 주소와 비디오 옵션을 작성하다가 내역에서 과거 오디오 요청을 다시 실행해도 작성 중이던 주소와 비디오 옵션은 남아 있다. 오디오 재요청이 실제 접수되면 이후 새 입력에 사용할 기본값만 갱신한다.
- 자막 재요청의 파일 선택을 취소하면 새 요청을 만들지 않고 작성 중인 입력과 기억한 기본값을 유지한다.
- 접수에 성공한 뒤 같은 추출 화면에 머무르면 진행·결과를 계속 본다. 다른 메뉴로 이동했다가 돌아오면 새 요청을 준비하고, 이전 작업은 내역에서 찾는다.

## 확정한 모바일 노출 기준

- 390×844px, 기본 글자 크기, 보조 설명이 접힌 일반적인 입력 상태에서는 제출 버튼 전체가 스크롤 없이 보인다.
- 더 작은 화면, 긴 파일명, 글자 확대에서는 스크롤을 허용한다.
- 끝까지 스크롤하면 모든 조작을 하단 탭 위에서 온전히 사용할 수 있어야 한다. 모바일 하단 탭의 높이와 안전 여백을 본문 배치에 반영한다.

## 출발점인 다섯 점검 항목

| 항목 | 현재 확인한 사실 | 재설계 대응 |
| --- | --- | --- |
| 내역의 다시 요청 | 요청 종류별 입력 화면으로 이동하며 원래 입력 조건은 전달하지 않는다. 현재 내역 문서도 화면 이동만 약속한다. | 영상·오디오는 같은 조건으로 즉시 실행하고, 자막은 파일 선택 후 이전 처리 방식으로 실행. 입력 초안은 유지하며 별도 확인창을 생략. |
| 텍스트 대비 | 일부 보조 텍스트가 대체 표면에서 충분한 대비를 확보하지 못한다는 기존 브라우저 점검이 있다. 헤더의 브랜드명에도 낮은 대비가 보고됐다. | 새 색 체계의 읽기 쉬운 텍스트와 배경 조합 |
| 주소 입력의 접근성 이름 | 입력을 감싼 label에 안내문과 지우기 버튼이 함께 있어 이름이 입력 상태에 따라 달라진다. | 입력의 이름을 일정하게 유지하는 화면·접근성 계약 |
| 자막 제출 버튼 | 선택 파일 행이 추가되면 390×844 화면에서 제출 버튼 일부가 고정 하단 탭에 가려지는 기존 캡처가 있다. | 하단 탭을 유지하고, 파일 선택 전후 같은 영역을 사용해 중복 공간을 줄임. 390×844 기본 입력 상태의 전체 버튼 노출과 안전한 스크롤을 충족해야 함. |
| 완료 진행 막대 | 완료 상태 라벨은 초록색이지만 진행 막대는 처리 중 색으로 고정된다. | 완료 막대를 제거하고 결과·다운로드 중심으로 표시 |

브랜드명은 일반 텍스트 대비 기준의 예외가 될 수 있으므로 헤더 글자의 낮은 대비만으로 일반 텍스트 기준 위반이라고 단정하지 않는다. 이 재설계에서는 승인된 무채색 서비스 이름 방향과 가독성 목표로 처리한다. 근거: [공식 최소 대비 설명의 로고·브랜드명 예외](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

## 기존 문서와의 관계

- [현재 디자인 계약](../../docs/DESIGN.md)은 Web과 확장 프로그램에 공통인 빨간 액션 색을 정의한다. 이번에 합의한 무채색 액션은 Web 재설계의 새 방향이며, 구현되어 있다는 뜻이 아니다.
- [기존 레이아웃 개선 명세](../web-layout-modernization/spec.md)는 하단 고정 내비게이션, 준비 상태 화면, 공통 단계 표시를 유지하도록 정했다. 새 설계에서는 모바일 하단 탭을 유지하고, 준비 상태 표현을 변경하며, 공통 단계 표시를 제거한다.
- [요청 내역 계약](../../docs/web/routes/history.md)의 다시 요청은 같은 종류의 입력 화면으로 이동한다. 새 설계에서는 영상·오디오는 같은 조건으로 바로 실행하고, 자막은 파일을 다시 선택하면 실행한다. 입력 화면으로 이동하지 않는다.
- 이번에 합의한 재설계 범위는 Web의 세 화면과 공통 화면 요소다. 공통 디자인 문서를 정리할 때 이 범위가 드러나도록 한다.

## 합의 상태

- 입력·내역·재요청에 관한 주요 동작과 2차 시안의 배치가 합의됐다. 현재 설계 범위에서 추가 사용자 결정이 필요한 미결 질문은 없다.
- 사용자 요청에 따라 [구현 명세](spec.md)를 작성하고 `ready-for-agent`로 등록했다. 승인된 요구사항과 구현·검증 기준은 이 명세에서 확인한다.
- Q19의 입력 교체 확인은 최종 재요청 방식에서 필요하지 않아 폐기했다.
- 이번 합의는 설계·문서화 범위이며 제품 코드 수정 승인을 포함하지 않는다.

## 시안 검토 기록

- [1차 시안](mockups/v1/README.md): 모바일 세 화면과 데스크톱 다크 테마의 화면 구성을 제시했다.
- 사용자 피드백: 헤더 오른쪽 `더보기`를 `…` 같은 아이콘으로 대체하고, 데스크톱 상단 탭의 레이아웃 배치를 재설계하도록 요청했다.
- [2차 시안](mockups/v2/README.md): 네 화면의 헤더에 가로 점 세 개를 적용했다. 데스크톱에는 왼쪽 세로 메뉴·오른쪽 작업 영역을 제안하고, 형식·화질 선택을 나란히 배치했다.
- 사용자가 `오케이 시안 좋음`으로 2차 시안을 승인했다. `…` 아이콘, 왼쪽 메뉴·오른쪽 작업 영역, 형식·화질의 가로 배치를 채택한다. 이미지의 예시 자료나 정확한 픽셀 값까지 구현 계약으로 고정한 것은 아니다.

## 후속 구현에서 유지·확인할 기존 경계

- 접수 진행 중에는 현재의 내비게이션 이동 잠금과 요청 취소를 유지한다. 미제출 입력을 메뉴 이동 동안 보존한다는 합의가 접수 중 이탈까지 허용한다는 뜻은 아니다.
- 취소 또는 접수 실패 후에는 원본 입력을 유지한다. 같은 화면의 작업 실패 뒤에도 보유 중인 파일을 다시 고를 필요 없이 입력을 조정할 수 있어야 한다. 내역에서 자막 재요청을 시작할 때의 파일 재선택과 구분한다.
- 내역의 재요청에도 기존 입력 검증·서비스 준비 확인·중복 제출 방지를 적용한다. 재요청이 접수되면 별도 내역으로 추적하고, 접수 실패 시 기존 내역과 작성 중인 입력을 유지한다.
- 접수 성공 뒤에는 저장된 접수증으로 내역에서 요청을 추적한다. 브라우저 저장 실패 시 현재 세션의 내역 연결로 접근하는 기존 경계를 유지하며, 새로고침 후 복구까지 보장한다고 표현하지 않는다.
- 내역 삭제는 접수증 삭제이며 서버 작업 취소가 아니다. 기존 삭제 되돌리기와 키보드 포커스 복구를 유지한다.
- 제목·원본 주소·파일명은 사용자가 요청을 구분할 수 있어야 하고, 긴 내용은 줄바꿈과 스크롤로 접근할 수 있어야 한다.
- 기존 자체 아이콘은 외부 얇은 선 아이콘 라이브러리에 의존하지 않는다. 필요한 기능 아이콘의 일관성을 유지하며 라이브러리 교체 자체를 목표로 삼지 않는다.
- 원본 입력의 접근성 이름은 값이나 보조 버튼에 따라 바뀌지 않아야 한다. 키보드 조작, 실제 클릭 영역, 초점 표시, 상태 공지와 일반 텍스트 대비를 새 화면에서도 검증한다.
- 화면 구성 검증은 라이트·다크, 320px·390px·데스크톱 폭, 글자 확대, 긴 제목·파일명, 파일 선택 전후, 준비 확인·장애·접수·처리·완료·실패·만료 상태를 포함한다. 로컬 브라우저 결과와 물리 기기·화면 낭독기·실제 처리 환경의 검증은 구분한다.

## 입력과 복원에 관한 현재 코드의 경계

다음은 현재 동작을 읽기 전용으로 확인한 사실이며, 새 설계의 승인 항목과 구분한다.

- 미제출 주소와 로컬 파일은 요청 화면을 벗어나거나 새로고침하면 사라진다. 형식·품질·자막 처리 방식만 브라우저에 기억하며, 현재는 사용자가 선택할 때 저장한다.
- 접수된 작업의 진행·결과 화면도 해당 요청 화면에 속한다. 메뉴 이동이나 새로고침 후에는 정상 저장된 접수증을 통해 요청 내역에서 상태를 다시 조회한다.
- 현재 완료 화면의 `새 요청`과 오류 화면의 `요청 설정으로 돌아가기`는 주소·파일·선택값을 유지한다. 새 설계에서는 완료 후 `새 요청`이 원본 주소·파일을 비우도록 변경한다.
- 같은 요청 화면에서 실패한 경우에는 선택한 로컬 파일이 남아 있다. 요청 내역의 자막 재요청은 파일명·처리 방식만 조회할 수 있으므로 원본 파일을 다시 선택해야 한다.
- 실패·만료 상태를 정상 조회하면 영상의 원본 주소·형식·품질, 자막의 파일명·처리 방식을 확보할 수 있다. 영상 주소는 같은 영상을 가리키는 정규화된 주소이며, 이전 주소의 부가 질의 문자열까지 복원하는 것은 아니다.
- 요청 상태를 조회하지 못하면 복원할 조건도 확보할 수 없다. 현재 내역은 조회 오류에서 다시 확인 동작을 제공하며, 요청 기록 자체가 없어 404를 받으면 해당 접수증을 제거한다.

## 조사와 구현의 구분

2026-09-29 인계는 로컬 브라우저와 임시 응답을 사용한 점검 및 캡처에 근거한다. 2026-10-02 읽기 전용 재확인에서 다섯 항목과 관련 코드·문서가 같은 상태임을 확인했다. 이 설계 인터뷰에서는 제품 코드를 변경하거나 새 브라우저 검증을 실행하지 않았다. 제안한 재설계의 동작과 접근성이 검증됐다는 의미는 아니다.
