# 요청 내역의 요청 영상 제목 표시

상태: Q1–Q5 합의 완료. 사용자의 스펙 작성 요청에 따라 구현 명세로 구체화함.

## 문제

Web 앱의 요청 내역에서 영상 요청은 고정된 종류 이름으로 표시되어 어떤 영상을 요청했는지 구분하기 어렵다.
현재 서버는 결과물에 원본 제목을 저장하지만 상태 응답에는 포함하지 않는다. 제목은 추출 완료 후 저장되며 결과물 정리 시 함께 삭제된다.

## 합의한 결정

- Q1: 제목을 확보한 시점부터 표시하며, 확보한 제목은 요청 실패와 결과물 만료 이후에도 유지한다. 제목 확보 전이나 조회 실패 시 원본 영상 링크로 요청을 구분한다.
- Q2: 요청 영상 제목을 목록 항목의 주 제목으로 표시한다. 비디오·오디오 구분, 품질, 요청 시각은 보조 정보로 둔다. 오디오 추출도 포함하고 자막 요청은 제외한다.
- Q3: 요청에서 처음 확보한 제목을 유지한다. 이후 YouTube 제목이 바뀌어도 갱신하지 않고, 내역을 열 때 최신 제목을 재조회하지 않는다.
- Q4: 기존 요청은 서버에 제목이 남아 있는 경우 반영한다. 이미 삭제되었거나 수집하지 못한 과거 제목은 외부에서 재수집하지 않고 원본 영상 링크로 표시한다.
- Q5: 접수 즉시 별도 조회를 추가하지 않는다. 기존 추출 처리에서 제목을 얻는 즉시 저장·표시한다. 대기 중이거나 확보 전에 실패한 요청은 원본 링크로 구분하며, 제목 조회 실패 자체가 추출을 실패시키지 않는다.

## 완료 조건

- 영상·오디오 요청은 제목이 있으면 이를 주 제목으로 표시하고, 없으면 원본 영상 링크로 식별할 수 있다.
- 처리 도중 확보한 제목은 완료를 기다리지 않고 상태 조회에 반영된다.
- 확보 이후 추출이 실패하거나 결과물이 만료·정리되어도 요청의 제목이 유지된다.
- 기존 요청의 남아 있는 제목도 표시되며, 제목이 없는 과거 요청 때문에 외부 조회가 발생하지 않는다.
- 새로고침 이후에도 같은 제목을 표시하며, 원본 제목 변경 때문에 기존 요청의 제목이 바뀌지 않는다.
- 제목 조회 실패에도 기존 추출 처리를 계속한다.

## 후속 구현에서 지킬 경계

제목을 결과물 삭제와 독립적으로 보존할 서버 저장 방식과 기존 제목의 이관 절차는 후속 구현 설계에서 구체화한다.
현재 브라우저 접수증의 식별 정보 저장 계약과 상태 조회·다운로드·삭제·되돌리기 동작을 유지한다.
이 문서는 인터뷰 결정 기록이며 구현 명세나 작업 티켓은 아니다. 제품 코드는 아직 변경하지 않았다.
