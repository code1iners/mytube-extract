# 03: 신규 추출의 제목을 확보 즉시 표시

**What to build:** 신규 영상·오디오 추출에서 제목을 얻으면 완료 전에 요청 내역에 표시하고, 이후 추출이 실패해도 같은 제목을 유지한다. 제목을 얻지 못하더라도 기존 추출을 계속하고 원본 링크로 요청을 식별한다.

**Blocked by:** 01 작업 처리 진입점 분리, 02 재사용 결과물의 제목 보존과 내역 표시.

Status: ready-for-agent

- [ ] 기존 제목 조회에서 유효한 제목을 얻으면 다운로드·업로드 완료 전에 요청에 저장한다. 제목 확보를 위해 기존 사전 검증과 추출 순서를 바꾸거나 접수 시 별도 조회를 추가하지 않는다.
- [ ] 조건부 저장으로 처음 확보한 유효한 제목만 보존한다. 중복 처리·동시 저장 시도·다른 제목을 반환하는 재실행에서도 이미 저장한 제목을 덮어쓰지 않는다.
- [ ] 제목 조회 실패나 공백뿐인 결과는 미확보로 처리하며 다운로드를 계속한다. 저장 실패를 제목 보존 성공으로 보고하지 않고 기존 오류 처리와 구분한다.
- [ ] 제목 확보 전 실패한 요청은 원본 링크를 제공하고, 확보 후 다운로드 또는 업로드가 실패한 요청은 제목을 유지한다.
- [ ] 기존 상태 조회 주기에서 링크가 제목으로 바뀐다. 제목 전용 반복 조회, 종료 상태의 반복 조회, 제목 변경에 대한 반복 공지를 추가하지 않는다.
- [ ] 01의 실제 처리 진입점과 02의 로컬 데이터베이스 검증 경계를 사용한다. 제목 확보 직후 다운로드를 일시 정지하고 실제 서버 상태 조회에서 완료 전 제목을 확인한다.
- [ ] 같은 요청을 실패로 종료한 뒤 재조회하여 제목 보존을 확인한다. 제목 조회 실패 후 추출 성공과 제목 확보 전 실패도 검증한다.
- [ ] 실제 로컬 데이터베이스에서 경쟁하는 제목 저장 시도와 재실행을 검증하여 첫 저장값이 유지됨을 확인한다. 대역 기반 처리 검증을 실제 외부 추출 성공으로 표현하지 않는다.
- [ ] 기존 브라우저 검증에서 처리 중 링크 → 제목 전환과 실패 후 제목 표시를 확인하고, 마지막 변경 이후 관련 정적 검사·최신 작업 처리기 빌드·테스트를 통과한다.

## 범위 경계

과거 제목 재조회, 새로운 재시도 정책, 최신 YouTube 제목 동기화는 포함하지 않는다. 광범위한 작업 처리 구조 변경은 01의 경계를 재사용하여 피한다.
