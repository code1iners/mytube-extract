# 04: 기존 요청의 남아 있는 제목 이관

**What to build:** 기존 요청에 연결된 결과물의 제목을 요청으로 이관하여 내역에서 확인할 수 있게 한다. 제목이 없어진 과거 요청은 외부 복구 없이 원본 링크로 표시한다.

**Blocked by:** 02 재사용 결과물의 제목 보존과 내역 표시.

Status: ready-for-agent

- [ ] 요청 제목이 미확보이고 연결된 결과물에 유효한 제목이 있는 요청만 이관한다. 이미 확보한 제목은 변경하지 않는다.
- [ ] 결과물이 없거나 제목이 null·빈 문자열·공백뿐이면 미확보로 남긴다. 제목 없는 과거 요청을 삭제하거나 실패 상태로 바꾸지 않는다.
- [ ] 같은 결과물을 참조하는 여러 요청에 제목을 각각 보존한다. 이관 후 결과물 정리로 각 요청의 제목이 사라지지 않는다.
- [ ] 반복 실행 및 중단 후 재실행에 안전한 이관 수단을 제공한다. 요청 제목이 중간에 확보된 경우에도 덮어쓰지 않도록 조건부 갱신한다.
- [ ] 이관과 이후 내역 조회에서 외부 제목 조회가 발생하지 않음을 검증한다. 현재 저장값만 사용한다.
- [ ] 실제 로컬 데이터베이스에 테스트 소유의 제목 있는 결과물·없는 결과물·결과물 없는 요청·기존 요청 제목·공유 결과물을 준비해 이관 전후와 재실행 결과를 확인한다.
- [ ] 이관된 요청을 서버 상태 조회로 읽어 저장된 제목을 확인하고, 기존 내역 화면에서 표시되는 것을 브라우저 경계로 확인한다. 제목 미확보 과거 요청은 링크를 유지한다.
- [ ] 이관 대상·반영·미확보 상태를 확인하는 방법과 실패 시 재실행 방법을 문서화한다. 06에서 전환 절차와 연결할 수 있게 한다.
- [ ] 마지막 변경 이후 관련 정적 검사와 이관·상태 조회 테스트를 실행한다. 테스트 환경 부재나 빈 대상에 따른 미실행을 성공으로 기록하지 않는다.

## 범위 경계

운영 데이터 이관 실행은 포함하지 않는다. 정리 작업과 이관의 전환 순서 및 구 버전 잔여 실행은 06에서 로컬 검증한다. 03 완료를 기다릴 필요 없이 02의 저장·응답 계약으로 검증할 수 있다.
