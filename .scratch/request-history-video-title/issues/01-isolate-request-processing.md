# 01: 작업 처리 진입점 분리

**What to build:** 사용자가 경험하는 추출 동작을 유지하면서 요청 한 건의 처리를 독립적으로 실행·검증할 수 있게 한다. 후속 제목 보존 작업에서 제목 확보 직후와 다운로드 완료 전을 제어할 수 있도록 최소한의 사전 정리를 수행한다.

**Blocked by:** 없음 (즉시 시작 가능).

Status: ready-for-agent

- [ ] 기존 작업 반복 실행에서 요청 한 건을 처리하는 진입점을 분리하고 실제 작업 처리기가 해당 진입점을 사용한다. 테스트 전용으로 복제한 처리 흐름을 만들지 않는다.
- [ ] 제목 조회와 다운로드·업로드를 외부 의존성 경계에서 제어할 수 있다. 작은 저장 함수마다 새 경계를 만들지 않고 단일 요청 처리 경계를 우선한다.
- [ ] 결과물 재사용, 사전 검증, 제목 조회, 다운로드, 업로드, 완료·실패 전환의 기존 순서와 동작을 유지한다.
- [ ] 비디오·오디오의 기존 추출 정책, 재시도, 임시 파일 정리 및 오류 계약을 변경하지 않는다.
- [ ] 제어된 실행으로 요청 한 건의 성공·실패·결과물 재사용을 검증한다. 다운로드를 일시 정지했다가 완료하는 테스트가 실제 진입점을 통과한다.
- [ ] 제목 저장 필드나 화면 변경은 이 티켓에 포함하지 않는다. 기존 데이터 저장·서버 응답 동작이 유지됨을 확인한다.
- [ ] 마지막 변경 이후 작업 처리기 정적 검사와 최신 빌드를 사용하는 관련 테스트를 통과한다. 외부 실행 대역의 결과를 실제 YouTube 성공으로 표현하지 않는다.

## 범위 경계

선행 사전 정리 예외에 해당한다. 작업 처리 전체의 재설계나 스케줄러 변경을 포함하지 않는다. 02와 독립적으로 시작할 수 있으나, 여기서는 결과물 재사용의 제목 복사 동작을 추가하지 않는다.
