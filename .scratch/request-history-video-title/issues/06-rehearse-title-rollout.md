# 06: 데이터 유실 없는 전환 절차와 통합 확인

**What to build:** 기존 요청과 새 요청 모두에서 제목을 잃지 않고 개선을 적용할 수 있도록 전환·복구 절차를 문서화하고 로컬에서 검증한다. 운영 배포 없이 전체 계약의 준비 상태를 확인한다.

**Blocked by:** 03 신규 추출의 제목을 확보 즉시 표시, 04 기존 요청의 남아 있는 제목 이관, 05 긴 제목과 내역 조작 검증·보완.

Status: ready-for-agent

- [ ] 필드 추가 → 기존 제목 이관 → 새 저장·응답·표시 활성화의 호환 가능한 전환 순서를 문서화한다. 결과물 정리가 이관 전 제목을 지우지 않도록 정리 작업 통제 시점과 재개 조건을 명시한다.
- [ ] 구 버전 작업 처리기의 잔여 실행 종료를 확인하고, 그 실행이 결과물에만 남긴 제목을 누락분 이관으로 보존한 뒤 정리를 재개하는 절차를 포함한다.
- [ ] 로컬 테스트 소유 데이터에서 이관 중 잔여 구 버전 완료 상황을 재현하고, 누락분 이관 및 실제 결과물 행 정리 후 서버 조회에도 제목이 남음을 확인한다. 이를 운영 환경 성공으로 표현하지 않는다.
- [ ] 전환의 중단 조건, 이관 실패 후 재개, 이전 코드 복구 방법을 기록한다. 복구 시 추가 필드나 확보한 제목을 삭제하지 않으며, 구 버전 복구 중 정리 재개로 제목이 유실되지 않도록 한다.
- [ ] 기존 02–04의 실제 로컬 데이터베이스 검증을 재사용해 재사용 요청·신규 처리·실패·만료·과거 이관의 보존 계약을 확인한다. 내부 테스트 경계를 새로 중복 구축하지 않는다.
- [ ] 기존 브라우저 검증으로 제목·원본 링크·종류·품질·새로고침·삭제·복원 및 자막 회귀를 최종 확인한다. 이전 티켓의 검증을 대신하는 첫 검증 단계로 사용하지 않는다.
- [ ] 실제 구현에 맞춰 요청 내역의 서버 정보·저장 계약 문서를 갱신하고, 브라우저 접수증 계약 및 요청 기록 존재 기간과 제목 보존의 관계를 명확히 한다.
- [ ] 마지막 변경 이후 관련 정적 검사·최신 빌드·자동 테스트를 실행하고, 로컬 데이터베이스 통합·브라우저 대역·실제 외부 환경 증거를 구분하여 기록한다. 환경 부재로 실행하지 못한 필수 검증이 있으면 완료로 표시하지 않는다.
- [ ] 운영 배포, 운영 데이터 이관, 실제 YouTube 추출은 실행하지 않는다. 실제 외부 추출은 이 기능의 필수 검증으로 추가하지 않는다.

## 범위 경계

새 기능이나 광범위한 정리 작업을 추가하는 마무리 티켓이 아니다. 전환 절차에 필요한 제한적인 보완과 계약 문서 갱신만 포함한다. 부모 스펙의 상태를 변경하거나 닫지 않는다.
