# 05: 긴 제목과 내역 조작 검증·보완

**What to build:** 긴 제목이나 원본 링크가 있어도 좁은 화면에서 요청을 구분하고 다운로드·삭제·되돌리기를 사용할 수 있게 한다. 키보드 탐색과 기존 내역 동작을 함께 유지한다.

**Blocked by:** 02 재사용 결과물의 제목 보존과 내역 표시.

Status: ready-for-agent

- [ ] 긴 한글·영문 제목, 공백 없는 문자열, 긴 원본 링크가 좁은 화면과 확대 상태에서 줄바꿈되며 주요 조작 영역을 가리거나 가로 넘침을 만들지 않는다.
- [ ] 제목이 있는 항목과 없는 항목 모두 접근 가능한 이름을 갖고, 원본 링크를 키보드로 탐색·실행할 수 있다. 제목과 링크 내용은 일반 텍스트로 취급한다.
- [ ] 삭제 후 다음 삭제 버튼, 이전 삭제 버튼, 빈 목록 제목으로 이동하는 기존 순서와 되돌리기 후 해당 항목 제목으로 실제 포커스가 이동하는 동작을 유지한다.
- [ ] 삭제·8초 되돌리기·저장 실패 및 다른 탭의 삭제·재추가 이후에도 정확한 요청과 서버 제목을 표시한다. 접수증에 제목이나 링크를 저장하지 않는다.
- [ ] 새로고침과 저장 차단 시의 기존 직접 링크 조회에서 제목·원본 링크 표시를 확인한다. 내역 정렬·요청 식별·다운로드·다시 요청 동작은 유지한다.
- [ ] 기존 브라우저 응답 대역으로 제목 갱신 시 항목 이름이 바뀌어도 포커스를 빼앗거나 반복 공지하지 않음을 확인한다. 03의 실제 제목 수집 완료를 선행 조건으로 삼지 않는다.
- [ ] 비디오·오디오의 구분과 보조 정보, 자막 내역의 기존 파일명 표시 및 조작이 유지됨을 확인한다.
- [ ] 가장 가까운 디자인 계약과 기존 내역 패턴을 따르며 필요한 화면 보완만 한다. 마지막 변경 이후 Web 정적 검사·단위 테스트·빌드·관련 브라우저 검증을 실행한다.
- [ ] 키보드와 실제 포커스 검증 결과를 기록하며, 보조 기술을 직접 확인하지 않았다면 해당 경계는 미검증으로 남긴다.

## 범위 경계

새로운 목록 디자인, 제목 검색·정렬·묶기, 자막 기능 변경은 포함하지 않는다. 데이터 보존과 이관 검증을 다시 구현하지 않고 기존 경계를 사용한다.
