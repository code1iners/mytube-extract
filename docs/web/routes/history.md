# Web Route `/history`

## Route

- path: `/history`
- source: `apps/web/src/app/pages/request-history/page.tsx`
- navigation: primary navigation `요청 내역` (desktop sidebar / mobile bottom tab)
- data source: browser `localStorage` 접수증과 job status API
- surface: 외곽 card 없이 workspace에 정렬된 구분선 목록·빈 상태 영역

## 사용자 흐름

1. 앱은 `mytube-extract:job-receipt:v2:<kind>:<jobId>` 건별 key를 읽는다.
2. 유효한 영상·자막 접수증을 `acceptedAt` 최신순 최대 20건의 단일 목록으로 표시한다.
3. `kind=video`는 `GET /downloads/:jobId`, `kind=subtitle`은 `GET /subtitles/jobs/:jobId`를 조회한다.
4. `queued`, `processing`, `extracting_audio`, `transcribing`은 2500ms 간격으로 polling한다.
5. `completed`, `failed`, `expired`에서는 polling을 중단한다.
6. completed와 API `downloadUrl`이 함께 있으면 attachment 다운로드 링크를 제공한다.
7. 정상 조회한 영상·오디오의 failed와 expired는 `다시 요청` 버튼 한 번으로 서버의 원본 주소·형식·품질을 재사용해 새 작업을 접수한다. 자막은 후속 티켓 08 전까지 입력 화면으로 이동한다.
8. 항목의 `상세`를 펼치면 원본 주소(제목이 있는 영상), 작업 식별자·접수 시각과 `내역에서 삭제`를 제공한다. 삭제 즉시 목록과 해당 localStorage key에서 제거되며 서버 작업은 취소하지 않는다.
9. 가장 최근 삭제 하나만 8초 동안 `되돌리기`로 같은 접수증을 복원할 수 있다. 복원은
   원래 `kind`, `jobId`, `acceptedAt`을 유지하고 최신순 위치로 다시 표시한다.

영상 상태 응답의 `title`이 유효하면 그 값을 항목의 주 제목으로 일반 텍스트 표시한다. 제목이
없으면 응답의 `sourceUrl`을 주 제목이자 접근 가능한 원본 링크로 표시해 같은 영상 요청을
구분한다. 자막은 원본 파일명을 제목으로 사용한다. 주 제목 아래에는 영상·오디오 구분과
품질 또는 자막 처리 방식(속도 우선·정확도 우선), 요청 시각을 항상 표시한다. 상태와
다운로드·다시 요청·조회 복구 행동도 상세를 열지 않고 사용할 수 있다. `다시 요청`은
영상·오디오에서는 내역 화면에 머물며 새 식별자의 접수증을 추가한다. 원래 요청의 상태·시각은 덮어쓰지 않는다.

반복 외곽 카드와 공통 단계 표시는 사용하지 않는다. 처리 중에는 서버가 제공한 0~100 범위의
진행률만 표시하고, 수치가 없거나 조회 오류·완료·실패·만료이면 막대를 숨긴다. 자막의
오디오 추출·자막 생성 상태는 각각 표시한다. 조회 오류는 작업 실패와 구분하여 내역을
보존한다. 다운로드 주소 없는 완료는 `파일 확인 필요`와 `다시 확인`을 제공한다.
정상 완료는 다운로드와 응답의 `retentionDays`에 따른 보관 안내를 표시하며 자막 결과는
`영어 SRT`로 설명한다.

긴 제목·원본 주소·파일명은 줄임표로 자르지 않고 줄바꿈한다. 주요 정보와 행동은 항상
보이며 부가 상세와 삭제만 기본으로 접힌다. `상세` 버튼은 항목 제목과 연결된 이름,
`aria-expanded`·`aria-controls`를 제공하며 Enter·Space로 열고 닫는다. 상태 갱신 중에도
상세 열림 상태와 포커스를 유지한다. 다운로드·다시 요청·상세·삭제·되돌리기 조작 영역은
44×44px 이상이며 200% 글자 확대에서도 줄바꿈·스크롤로 접근한다.

접수증이 하나도 없을 때는 빈 상태에서 `영상 추출`과 `자막 추출`을 동등한 시작점으로
제공한다. `시작할 작업을 선택하세요.`를 먼저 보여주고, 영상 추출은 YouTube URL에서
영상·오디오 파일을 받으며 자막 추출은 로컬 영상에서 영어 SRT 자막을 만든다는 출발
입력과 결과를 각 링크에 짧게 설명한다. 이력은 현재 브라우저에만 저장되고 완료 파일은
7일 동안 보관된다는 운영 모델도 별도 note로 한 번 안내한다. 이 정보는 전역 안내에만 의존하지 않고
빈 상태와 완료 항목의 관련 위치에서 다시 확인할 수 있다.

## 영상·오디오 다시 요청

- 서버 상태 조회에 성공한 실패·만료 항목만 실행한다. 정규화된 원본 주소와 형식·품질을 기존 입력 규칙으로 검증한다. 조건이 없거나 조회가 실패하면 `다시 확인`으로 복구하고, 404는 기존 정리 규칙을 따른다.
- 목록 전체의 `useHistoryAcceptance`가 기존 영상 어댑터와 추출 요청 생명주기를 한 번 연결한다. `trackAcceptedJob: false`로 접수 이후 조회를 기존 내역 목록에 맡긴다. 자막도 같은 공통 제어에 연결할 수 있으며 항목별 생명주기를 만들지 않는다.
- 접수 직전 준비 상태를 다시 확인한다. 시작한 행에서 접수 중 상태·접수 취소·실패 이유·준비 상태 복구를 제공한다. 접수 중에는 다른 재요청·내역 삭제와 메뉴 이동을 막는다. 취소 후 해당 항목 제목, 성공 후 새 항목 제목으로 포커스를 보낸다.
- 취소는 서버 작업 취소가 아니다. 늦게 성공 응답이 오면 생명주기의 접수증 저장 경계를 통해 새 내역을 보존한다. 접수 후 준비 오류는 기존 항목의 작업 상태를 바꾸지 않는다.
- 실제 서버 생성 응답을 받은 뒤에만 재사용한 형식·품질을 이후 기본값으로 기억한다. 조회·접수 실패·접수 전 취소에서는 기본값을 바꾸지 않는다. 영상과 자막의 미제출 초안은 읽거나 덮어쓰지 않으며, 복원도 기본값을 다시 저장하지 않는다.
- 저장 실패 접수증은 같은 탭 메모리에서도 유지해 메뉴 이동 후 내역에 접근한다. 새로고침 후 복구는 보장하지 않는다. 선택값 저장 실패도 기존 세션 선호 규칙을 따른다.

## 저장 계약

- 접수증은 `kind`, UUID `jobId`, ISO `acceptedAt`만 포함한다.
- 영상 제목과 원본 링크는 접수증에 저장하지 않고 매번 상태 API 응답에서 읽는다.
- 접수증은 서버 요청을 가리키는 브라우저 포인터일 뿐이다. 접수증을 삭제하거나 되돌려도
  서버 `ExtractionJob`과 그 안의 요청 제목은 변경하지 않으며, 제목은 결과물 asset 보관
  기간이 아니라 서버 요청 기록이 존재하는 동안 보존된다.
- 상태, 진행률, 메시지, 파일명, `downloadUrl`은 저장하지 않고 서버 응답만 사용한다.
- 손상된 접수증은 해당 key만 제거하며 다른 storage 값은 건드리지 않는다.
- network/5xx에서는 항목을 유지한다. 404에서만 해당 접수증을 제거한다.
- native `storage` event의 접수증 key와 `newValue`로 다른 탭의 정확한 추가·삭제·재추가를 반영한다.
- 다른 탭에서 삭제한 현재 deep link 접수증은 저장 목록 fallback으로 되살리지 않는다.
- 유효한 `kind`와 UUID query가 있으면 저장 목록에 없어도 deep link 항목을 조회한다.
- localStorage 실패 시 deep link 조회를 유지하고 저장 실패 안내를 표시한다.
- 삭제한 접수증의 복원은 저장 직후 재조회로 성공 여부를 확인한다. 접근·유효성 검증에
  실패하면 삭제 상태를 유지하고 성공 공지를 보내지 않는다.
- 삭제·복원은 receipt key와 서버 job을 제외한 다른 receipt, 원본 URL·파일명, 다운로드
  자산을 변경하지 않는다. route 이동이나 unmount에서 삭제를 다시 commit하지 않는다.

## 접근성

- 상태는 텍스트와 아이콘을 함께 사용하고 색만으로 전달하지 않는다. 만료 글자는 비활성색 대신 대비가 충분한 보조 텍스트색을 사용한다.
- 동일 polling 결과는 live region에 반복 알리지 않고 실제 상태 전이와 삭제만 polite status로 알린다.
- 항목 삭제 뒤 다음 항목의 보이는 주요 행동, 이전 항목의 보이는 주요 행동, 목록 제목 순으로 focus를 돌린다. 항목에 주요 행동이 없으면 상세 펼치기로 이동하며 닫힌 상세의 삭제 버튼에는 이동하지 않는다.
- 삭제 뒤에는 단일 undo 안내와 동작을 표시하고, 복원 성공 시 복원된 항목 제목으로
  focus를 이동한다. 복원 실패는 하나의 `alert`로 알리고 삭제된 목록 상태를 유지한다.
- layout은 `docs/DESIGN.md`의 색·간격·radius·760px content token을 재사용한다.
- 보조 `설정` 링크는 헤더의 `더보기` disclosure 안에 제공하며 테마 선택은 `/settings`에서 관리한다.
