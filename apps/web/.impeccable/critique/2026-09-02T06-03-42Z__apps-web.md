## Design Specificity Verdict

**부분적으로 제품 전용이지만, 본문 구조는 범용 변환기·관리 콘솔과 교환 가능하다.** 추출 마크, Nintendo red, 영상·자막·요청 내역이라는 정보 구조는 제품을 식별한다. 하지만 `.console-hero`, `.console-panel`, `.segmented-control`과 760px 단일 열이 모든 화면을 같은 회색 카드 흐름으로 평준화한다. 영상은 `URL → 형식 → 품질`, 자막은 `파일 → 처리 방식 → SRT`라는 서로 다른 작업인데 레이아웃의 표정은 거의 같다.

자동 탐지기는 1건을 냈다. `coverage/base.css:6`의 `font-family: Helvetica`지만 앱에서 로드되지 않는 coverage 산출물이라 오탐이다. 실제 `body`에는 Pretendard Variable이 적용됐다. 탐지기는 의존성 부재로 정규식 폴백(DEGRADED)을 사용했으므로 CSS selector와 computed contrast는 평가하지 못했다.

브라우저의 mutable injection이 불가능해 사용자에게 보이는 overlay는 만들지 못했다. 대신 새 Chrome 탭에서 `/video`, `/subtitles`, `/history`, `/settings`를 데스크톱과 390×844로 검사했고 수평 overflow나 고정 하단 탭의 콘텐츠 가림은 발견하지 않았다.

## Overall Impression

정돈은 됐지만 세련되지는 않았다. 색과 폰트는 이미 현대적이고 접근성 기반도 좋은데, **헤더도 카드, 상태도 카드, 폼도 카드, 선택지도 작은 카드**라 모든 것이 같은 목소리로 말한다. 가장 큰 기회는 장식을 더하는 것이 아니라 작업 흐름의 계층을 다시 세우고, 시스템 상태를 조용한 보조 정보로 내리는 것이다.

## What's Working

1. 데스크톱 상단 3분할 탭과 모바일 하단 탭이 같은 세 목적지를 유지해 위치 인지가 좋다.
2. `aria-live`, progressbar, fieldset/legend, 44–48px 높이, 색 외 underline을 함께 쓴 선택 상태 등 접근성 의미가 구조에 내장돼 있다.
3. 빈 요청 내역은 영상·자막 시작점을 제공하고 로컬 이력·7일 보관을 설명해 막다른 길을 만들지 않는다.

## Priority Issues

### [P1] 모든 기능을 같은 카드 문법으로 처리해 위계가 평평하다

- **왜 중요한가**: 패널, 상태, 입력, 선택지가 비슷한 border·radius·surface를 반복해 핵심 행동과 보조 정보의 무게가 비슷하다. 이것이 “템플릿형 관리 화면” 같은 인상을 만든다.
- **수정**: 페이지 바깥 카드 셸을 약화하거나 제거하고, 입력 흐름 자체를 주인공으로 만든다. 영상과 자막에는 서로 다른 단계 구조를 부여하되 토큰과 내비게이션 계약은 유지한다.
- **추천 command**: `$impeccable layout`

### [P1] 장애 상태가 가장 큰 콘텐츠인데 복구 정보는 가장 약하다

- **왜 중요한가**: `/video`, `/subtitles`에서 worker 실패 카드가 입력보다 먼저 나오며 API, tunnel, worker 중 점검 대상을 알려주지 않는다. 사용자의 목적보다 인프라 장애가 첫인상이 된다.
- **수정**: 정상 상태는 한 줄 compact status로 축약하고 실패만 확장한다. 실패 유형과 다음 점검 대상을 분리하며 CTA 아래 중복 사유는 제거한다.
- **추천 command**: `$impeccable distill` 후 `$impeccable clarify`

### [P1] 브라우저 유일 이력을 복구 없이 즉시 삭제한다

- **왜 중요한가**: 계정과 서버 목록이 없어 localStorage receipt가 job을 다시 찾는 유일한 표면이다. 실수로 삭제하면 접근 경로를 영구히 잃는다.
- **수정**: 삭제 직후 5–10초 undo toast를 제공하고 기존 focus 이동 처리는 유지한다.
- **추천 command**: `$impeccable harden`

### [P2] 모바일 자막 흐름이 결정을 한꺼번에 펼친다

- **왜 중요한가**: 390×844에서 readiness 카드, 220px dropzone, 두 처리 옵션이 CTA보다 앞선다. 가려지지는 않지만 핵심 행동까지 시각적 거리가 길다.
- **수정**: dropzone을 140–160px로 줄이고 처리 방식은 파일 선택 뒤에 공개하거나 기본 선택 요약 + 변경으로 접는다.
- **추천 command**: `$impeccable adapt`

### [P2] 작업 언어와 구현 언어가 혼재한다

- **왜 중요한가**: “속도 우선/정확도 우선” 바로 아래 `base.en`, `small.en`, `Whisper`, worker가 나타나 선택 결과보다 내부 구현을 먼저 이해하게 한다.
- **수정**: 결과 중심 설명을 전면에 두고 모델 식별자는 기술 정보 disclosure로 내린다.
- **추천 command**: `$impeccable clarify`

## Minor Observations

- 모바일 `/settings`는 상단 설정만 활성이고 하단 주요 탭에는 현재 위치가 없어 정보 구조 밖에 떠 있는 느낌이다.
- 실제 가시 터치 대상 중 상단 설정 링크는 40×44px, URL 리셋은 38×44px로 44×44px 목표보다 폭이 작다.
- `/history` 빈 화면은 내용이 유용하지만 설명, 빈 제목, 두 작업 설명, 로컬 보관 note가 겹쳐 문장량을 줄일 여지가 있다.
- `/settings`는 큰 독립 route에 테마 선택 하나만 있어 레이아웃이 미완성처럼 보인다.
- URL `리셋`은 값이 없을 때도 비활성 상태로 자리를 차지해 입력 행을 덜 조용하게 만든다.
